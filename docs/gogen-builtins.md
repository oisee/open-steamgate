## Limits and next oracle rows

- Numeric unary functions: i/f/p; nmin/nmax: i/f. Other operand types are not covered by these probes.
- String functions accept only the forms the frontend explicitly lowers; regexp and unusual offsets can be refused. The refusal text includes the specific unsupported argument or form.
- ipow: i and int8 use checked multiplication; packed decimal uses exact intermediate multiplication. The exponent converts to i and does not choose the result type. The wider of the base and numeric assignment target/enclosing calculation type applies (the supplied 758 oracle measures literal-base assignments). Exponent zero returns one, including zero base.
- The supplied 758 oracle measures negative exponents through float, rounded half away from zero on assignment to i/int8/p; f retains the fraction. Zero to a negative power raises catchable `CX_SY_ARITHMETIC_OVERFLOW`. The twelve supplied cases pass in Go and IR-as-JS.
- Next oracle row: standalone `lv_int8 = ipow( base = 2 exp = 40 )` computing in i and overflowing is unmeasured. The supplied `2**62` assignment succeeds in int8, so current lowering uses the int8 target; measure the proposed 40 row before changing that rule.
- String conversion: the supplied minimum-i oracle expects `-2147483648`, whereas the repository's previous assignment measurement uses a trailing sign (`2147483648-`). The emitted minimum-i conversion follows the supplied expectation as a compatibility exception; ordinary i/int8 assignment retains the trailing sign. Reconcile the minimum-i oracle with a direct assignment/WRITE measurement next. Float assignment uses scientific notation with sixteen fractional digits, separate from positional string templates.
- decfloat16/34 remain outside gogen's type subset, with `type DecFloat16Type is outside the subset` / `type DecFloat34Type is outside the subset`; never converted through a binary float. Next oracle rows: decfloat precision, rounding and exponent bounds before expanding that type subset.
- boolx: logical expression bridged through boolc to accommodate core's character-source signature; bit numbering starts at one at the most significant bit. Zero gives an empty xstring; negative positions fill the prefix. Bits beyond 524288 raise a named local allocation-limit refusal.
