Полезное ядро — ближе, чем «весь SQLScript». Для read-only аналитических AMDP нам нужны типизированные параметры, ветвления, joins, aggregates, windows, table results и одна транзакция. Значительная часть этого уже работает. Полная поверхность языка включает ещё mutation, DDL, dynamic SQL, handlers и специализированные библиотеки — она существенно дальше.

Как это устроено

JavaScript управляет. База считает отношения.

Мы не переводим SQLScript в гигантскую JavaScript-функцию и не делаем строки таблиц JS-массивами. IR сохраняет типы, NULL, зависимости и версии отношений.

1 · ABAP / AMDPНеизменённая сигнатура и исходное тело SQLScript.
2 · FrontendLexer, parser, имена, scope и точные типы.
3 · Typed IRControl nodes + immutable relational plans.
4 · RuntimeIF/WHILE/scalars в JS; step limits и trace.
5 · DatabaseОбычный SQL на HANA или DuckDB. Без fallback.

Работает

Реляционное ядро

SELECT, filters, inner/left joins, derived и correlated subqueries, EXISTS/IN, DISTINCT, UNION/UNION ALL, EXCEPT, GROUP BY/HAVING, ORDER BY/LIMIT.

Работает

Аналитика

ROW_NUMBER, RANK, DENSE_RANK, partitions, deterministic ties и агрегаты. Ranking fixture различает rank-with-gap и dense rank.

Работает

Control flow

DECLARE scalar, assignments, IF / ELSEIF / ELSE и WHILE. Есть ограничение шагов; зависание программы становится диагностикой.

Работает

Типы и NULL

INTEGER, часть packed decimal, fixed character, STRING, date storage, typed empty relations и явный SQL NULL. Непроверенные coercions отказываются.

Работает

Контекст и массив

CURRENT_USER, CURRENT_SCHEMA и literal SESSION_CONTEXT приходят из execution context. Fixed INTEGER ARRAY раскрывается с NULL, duplicates и ordinality.

Узкий baseline

Поиск

Exact/substring case над измеренным ASCII fixture исполняется на HANA и DuckDB. Настоящие fuzzy profiles вынесены в ADR 0002 и backlog.

Работает

Composition и LUW

Настоящий ABAP Unit, typed table boundary, nested AMDP и прямой catalogue read видят одну DuckDB-транзакцию. Незакоммиченная Open SQL строка доступна AMDP без копирования.

Не сейчас

Широкий imperative

FOR, general cursor OPEN/FETCH, handlers, dynamic SQL, mutation, temporary DDL и широкий набор built-ins.

Явная граница

Не portable по природе

XMLTABLE, HIERARCHY и часть HANA libraries могут остаться native-only. Refusal лучше похожего, но неверного результата.

Доказательства, не чекбоксы

Двенадцать вертикальных кейсов

SQUARES

Исходный WHILE, scalar snapshots и растущее отношение. Native HANA = portable HANA = DuckDB.

mix_rows

Два table inputs, joins, correlated EXISTS, DISTINCT, LIMIT и typed result.

rank_rows

Grouping, window ranks, ties и duplicate-eliminating UNION.

transform

Все ветки IF, regex и explicit session context.

identity_cells

Execution identity не заимствуется у случайного backend connection.

expand_values

Настоящий SQLScript ARRAY + UNNEST WITH ORDINALITY.

difference_cells

EXCEPT DISTINCT, duplicates и NULL row equality.

search_cells

Простой исполняемый search baseline; полный fuzzy честно отложен.

optional_value + scalar_value

RETURNING scalar, optional omission и zero database statements.

control_rows

Исполняется: typed unused cursor + sequential block с одним присваиванием в procedure output. Это не заявление о поддержке OPEN, FETCH или cursor loops.

Vector Workbench

Исходный AMDP с двумя DDIC scans и RAW(192) BITXOR/BITCOUNT работает на DuckDB; top-7 ids, ranks и payloads совпадают с независимым ANYDB oracle.

А как насчёт «всех примеров из книги»?

Пока нельзя назвать честный процент.

Книга уже использована как карта поверхности языка в docs/sqlscript-surface.md: мы знаем, какие семейства конструкций существуют. Но её листинги не оформлены как отдельный легальный runnable corpus, поэтому «N из M примеров книги» сейчас не измеряется.

Ближайший proxy — teaching corpus из A4H: documentation demos, compiler fixtures и unit-double demos. В нём сейчас lower целиком 17 из 101. Это не 17% книги, но хороший индикатор расстояния до учебной поверхности.

Чтобы получить настоящий book score: нужен отдельный clean-room набор листингов с ожидаемыми значениями и ошибками. После этого тот же runner даст точное parsed / typed / lowered / executed, не меняя архитектуру.
Почему broad coverage пока 4%

Несколько массовых границ, а не 348 независимых провалов

FROM table function19 lowered refusals

Catalogue closureseveral families

Хорошая новость

Corpus coverage растёт ступенями. Реализация одного корректного FOR или table-function node потенциально открывает десятки тел. Перед тем как писать очередную конструкцию, runner снова строит histogram: следующий шаг выбирается измерением, а не красотой синтаксиса.

Числа — blockers, а не обещание аддитивного прироста: одно тело может остановиться на следующей конструкции сразу после устранения первой.

Ближайший маршрут

От showcase к полезному ядру

✓ control_rows закрыт

HANA oracle исправил порядок DECLARE CURSOR; typed unused resource и sequential block с одним output-assignment совпали на native и portable paths. OPEN/FETCH по-прежнему вне claim.

✓ ABAP Unit → portable AMDP

Generated destination исполняет precompiled IR на системной DuckDB connection. Open SQL rows пересекают typed table boundary; empty input сохраняет schema; HANA fallback отсутствует.

✓ Nested AMDP, узкий честный срез

Один typed table IN → один table OUT; дочерний relation plan встраивается в родительский, call depth ограничен, DuckDB получает один финальный statement.

✓ Shared transaction и DDIC catalogue

Незакоммиченный ABAP SQL fixture виден прямому AMDP catalogue-read на той же системной DuckDB connection.

✓ Vector Workbench на Portable-AMDP

RAW(192), BITXOR/BITCOUNT и реальный top-K search выполняются в DuckDB; результат сверяется с ANYDB engine.

Ширина по histogram

FOR, table functions in FROM, client/session parameters и catalogue closure — в порядке реально разблокируемых тел.

После ядра

Versioned fuzzy profiles, mutation/handlers, второй embedded backend и clean-room book corpus.
