# Completeness critic

## Routes no spec covered

- GET /sap/bc/adt/debugger/listeners (tools/adt-facade.mjs:1711, registered in the loop `for (const method of ["get","post","delete"])`). No family spec covers it. Port-map lists it as 3 SKELETON rows that answer 200 with no body. The discovery spec even proposes it as the diff test's warm-up path on the grounds that it 'stays HOST', which contradicts the done criterion.
- POST /sap/bc/adt/debugger/listeners (tools/adt-facade.mjs:1711, same loop). No spec covers it. It answers res.status(200).end(): untyped, empty, no ETag.
- DELETE /sap/bc/adt/debugger/listeners (tools/adt-facade.mjs:1711, same loop). No spec covers it. It is a trivial static ABAP row, about S effort, and should go with discovery or sessions (stoker) or into the skeleton (dell).
- Covered by existing ABAP rows, so not missing, listed so the inventory is complete: GET /sap/bc/adt/core/http/systeminformation (:1717, ZCL_OSD_ADT_SYSINFO); POST {6 source collections + packages}/:name LOCK/UNLOCK (:2129, ZCL_OSD_ADT_LOCK); GET {src}/:name/source/main/versions[/:stamp/:version/content], DDLS :name/versions..., CLAS/INTF includes/:include/versions... (:1831-1847, ZCL_OSD_ADT_VERSIONS); HEAD/GET compatibility/graph (:1753/:1756, ZCL_OSD_ADT_GRAPH). ALL /sap/bc/adt/* (:3001) is the permitted HOST catch-all. The router.use middleware at :649 (sessions), :651 (X-OSD-Generation) and :669 (STG_ADT_DUMP) belongs to slice 3 front-up, not to any family.

## Inconsistencies

- PARSE versus OUTLINE. Port-map section 3 plans one STORE command PARSE with kinds OUTLINE, DDLS and UNIT_PLAN. The source-read spec instead defines a separate NEW STORE command OUTLINE. data-preview passes the kind in IV_TYPE ('DDLS'). abap-unit passes it in IV_JSON {kind:'UNIT_PLAN'}. Three encodings for one command: agree on PARSE with IV_JSON {kind,...} before B2b, C2a or C4b lands.
- PACKAGE command shape. checkruns wants PACKAGE IV_NAME -> ET_OBJECT rows (TYPE, NAME) holding raw store.package(...).objects with no $TMP author filter, plus EV_ERROR on a miss. information-system wants PACKAGE IV_NAME + IV_FILTER=user -> EV_JSON {found, ...} with localView applied (the $TMP author filter), subpackage descriptions and found:false on NotFound, and in addition a separate PACKAGES (OBJECTS) command that returns raw objects. A checkrun on $TMP through information-system's PACKAGE would drop other users' objects, which Node does not do. The two must agree on one command with a raw/local-view switch and one output (EV_JSON). ET_OBJECT's NAME is CHAR40 and PACKAGE is CHAR30, which truncates.
- Host error envelope, five variants. object-create-delete: EV_JSON {error:{code,message}} with EV_ERROR empty. abap-unit PARSE: EV_ERROR 'NOT_FOUND:<msg>' prefix. data-preview SQL: EV_ERROR plus EV_JSON {code,message,raw}. activation VERDICT: {refused:{code,message}}. introspection SYSTEM: {refuse:{status,type,message}}. ZCL_OSD_ADT_HOST should map exactly one convention to the ZCX factories.
- STORE READ extension, two encodings of the same fact. source-read adds EV_JSON {name, changedBy, empty}. write-includes 4a adds EV_STATE='empty'. activation wants EV_JSON {code} on READ errors. ddic and source-read instead pattern-match EV_ERROR CP '* does not exist'. Make it one additive EV_JSON {name, changedBy, empty, error:{code,message}}.
- STORE OBJECT extension is specified separately three times. source-read: package, changedAt, changedBy, version, includes. information-system: packages (the chain) and includes. editor-helpers-transport: package. All are additive and compatible, but they must land as one change. Otherwise three PRs edit #object and ZCL_OSD_ADT_HOST=>ty_object.
- Route access to the session, three designs. sessions-logoff adds TY_REQUEST-session (ty_session) plus a class-method ZCL_OSD_ADT_HANDLER=>SESSION( ) that returns the interface. object-create-delete adds TY_REQUEST-session plus TY_REQUEST-sessions TYPE REF TO zif_osd_adt_session and a new ZIF_OSD_ADT_SESSION~RELEASE_OBJECT. information-system adds TY_REQUEST-user and TY_REQUEST-pattern, while source-read adds TY_REQUEST-uri. write-includes 4a uses none of these and adds a SYSTEM kind LOCK_OF that answers from req.adt.session. One TY_REQUEST extension (session, sessions ref, pattern, uri) is needed, and LOCK_OF should be declared transitional.
- The percent-decoder is variously named and its failure mapping conflicts. abap-unit: ZCL_OSD_ADT_URI=>DECODE_COMPONENT raises invalid_request('URI malformed') (400). activation: DECODE_COMPONENT_STRICT raises internal('URI malformed') (500, osd namespace). checkruns: a decode_segment variant -> 500 osd. object-create-delete: a 'DECODE_COMPONENT variant that reports failure' -> 500 osd. transport: -> 500 ExceptionTransportCheckFailed com.sap.adt. abap-unit's DECODE_COMPONENT name collides with the others' semantics. Build one decoder that returns ok/failed, and let each route raise its own Node-equal refusal.
- Entity-tag helper, names and semantics. source-read: ZCL_OSD_ADT_ENTITY=>SEND. write-includes 4a: ZCL_OSD_ADT_ENTITY TAG/NORMALIZED (or on ZCL_OSD_ADT_XML). activation: ZCL_OSD_ADT_ENTITY TAG/NORMALIZED. ddic: ZCL_OSD_ADT_XML=>SEND_ENTITY or a new ZCL_OSD_ADT_ENTITY. Semantics per tools/adt-entity.mjs: normalizedTag (If-Match, activation) trims, strips one W/, and strips one leading and one trailing quote, with no comma split. sendEntity (If-None-Match) splits on ',' and then does the same per part. activation's 'strip W/, quotes' and versions' current 'remove all quotes' are both looser. Fix one class, ZCL_OSD_ADT_ENTITY, with TAG, NORMALIZED and SEND.
- Check-report builder exists twice: checkruns ZCL_OSD_ADT_CHECK_DOC=>REPORT_DOCUMENT( it_reports, iv_omit_empty_list ) and data-preview ZCL_OSD_ADT_CHECKREPORT. It is one Node function (checkReportDocument), so it should be one ABAP class.
- Continuation-to-ABAP re-entry has three shapes. activation: a FINISH( iv_json ) step on ZCL_OSD_ADT_ACTIVATION. abap-unit: a generic ZCL_OSD_ADT_HANDLER=>RESUME plus ZIF_OSD_ADT_RESUMABLE~RESUME, explicitly asking to agree on it with 4b. notebook: the host opens a second step calling ZCL_OSD_ADT_CLASSRUN=>RUN directly. Agree on one handler entry point. activation's req.osdFacade per-request lookup (the registry is process-global and tests mount many routers) must apply to every kind: activation, aunit-run, unit-object-run, NOTEBOOK_CELL.
- Where the continuation comes from. The notebook spec says the mechanism 'is introduced by slice 4b' and that 'no continuation exists'. In fact registerContinuation and ZIF_OSD_ADT_ROUTE=>TY_CONTINUATION exist on origin/feat/adt-front-up (tools/adt-abap-front.mjs:58-74), as activation and abap-unit correctly say. The notebook's dependency should be front-up plus the agreed re-entry step, not 4b.
- The same route is claimed twice. POST /sap/bc/adt/abapsource/occurencemarkers is in abap-unit (dell, slice C2a, 'occurencemarkers row') and in editor-helpers-transport (stoker, ZCL_OSD_ADT_OCCURRENCES). Pick one.
- Ownership conflicts with port-map. editor-helpers proposes stoker for the feeds and users, which port-map puts under SKELETON/dell. discovery proposes stoker for discovery, which port-map puts under SKELETON. introspection splits git to stoker and the rest to dell. Resolve these together with the debugger/listeners rows that no spec owns.
- Content-type replay. editor-helpers states that the front's res.send 're-sorts params and lower-cases the charset', so a non-normalized ABAP literal would pass the Node diff. In fact tools/adt-abap-front.mjs on main sets Content-Type with res.set and replays a Buffer (res.send(Buffer)). Express adds a charset only for text/* types without one and does no reformatting for Buffer bodies. ABAP's literal is the wire value, which is what activation and ddic say. Every ABAP content_type must therefore already be the normalized wire form, and the diff does see it.
- Weak ETag claims. discovery, checkruns, feeds, typestructure, activation and data-preview describe 'Express's weak ETag'. source-read and information-system note correctly that test/start.mjs:97 and osd-serve set app etag false, so production sends no weak ETag. Only the adt-abap-diff harness (a default express app) has one. Specs that pin weak-ETag or 304 behaviour pin a harness artefact. The 304-on-If-None-Match claims hold only there, and only strong sendEntity tags are real.
- Discovery ownership of advertise. The discovery family makes ZCL_OSD_ADT_DISCOVERY=>COLLECTIONS the source of truth, while transport, abap-unit and information-system say 'discovery stays Node's'. If discovery lands first, every later family PR must update the ABAP list in the same commit. That is not in their test plans.
- CAPABILITIES listing policy disagrees. checkruns adds CHECKRUN and data-preview adds SQL/SQLCHECK/PARSE to CAPABILITIES. abap-unit adds PARSE. source-read (OUTLINE), information-system (PACKAGE/PACKAGES/SEARCH), object-create-delete and activation explicitly do not, because CAPABILITIES drives the webgui screen buttons. One rule is needed, for example a separate 'commands' list for host detection.
- Git commands under two families. versions uses STORE HISTORY/REVISION. introspection puts git under SYSTEM kinds GIT_OBJECT/GIT_REVISION and proposes a 'new IV_REVISION pass-through', but IV_REVISION already exists on ZOSD_STORE. The git family should stay on STORE, as ADR 0007 names it, not SYSTEM.
- ZOSD_STORE IV_JSON. object-create-delete correctly adds IV_JSON as a new parameter (it is not in src/webgui/zosd_store.fugr.xml on main). abap-unit, activation and checkruns use IV_JSON as if it existed. information-system and data-preview say no new parameter is needed and overload IV_FILTER, IV_SOURCE and IV_LIMIT. Introduce IV_JSON once, together with the Go host key list, before any of them.
- ZCL_OSD_ADT_TYPES=>ALL( ) is defined five times with different columns. checkruns: collection, source flag. ddic: adt_type, label, plural, category. information-system adds TREE_* labels and STRU. activation adds the STRU fallback and a '' uri. transport adds a separate adt_type( ). Note that ADT_TYPE has 16 entries (STRU), while TYPES has 15.
- ABAP-FS conformance baseline is quoted as either 29 PASS / 2 FAIL / 16 MISSING (sessions, ddic, classrun) or 30/1/16 (create-delete, 4a, activation, abap-unit, information-system, editor-helpers). Fix one recorded baseline per slice.
- Miss-registry marker. source-read, ddic and information-system propose an X-OSD-Miss header (object|resource). introspection requires that its 404s record nothing, and information-system notes that nodepath records nothing either. The marker needs an explicit per-raise flag on ZCX_OSD_ADT=>NOT_FOUND, not a blanket rule that every ABAP 404 is a miss.

## Recommendations that break the design rules

- discovery-compatibility test plan. Switching the warm-up to 'GET debugger/listeners, which stays HOST' assumes a permanent HOST row other than the catch-all. That violates the done criterion. debugger/listeners must get ABAP rows too, so the warm-up needs a row that is HOST by construction, for example an unknown path that hits the catch-all.
- osd-introspection core/http/build. Porting it as an ABAP row is fine. The proposed liveness mitigation, 'answer build before the step in the front', is in effect a host-served route outside the table. It must be specified as a front pre-step bypass with no ABAP row involved, for example a host-only /osd/ready kept outside /sap/bc/adt. Otherwise `osd ready`, release smoke and osd-restart.sh time out behind any long step under design B. HEAD core/discovery (the discovery spec) has the same liveness issue: it is osd-restart.sh's probe, and the spec relies on the front's fallback only when the table cannot be read.
- osd-introspection git/object and transactions run inside the step: 4-6 synchronous execFileSync git calls, and a read of every *.clas.abap of every layer per request. These are not rebuilds, but they hold the work-process FIFO for host I/O whose cost grows with the tree. Either measure them and keep them, or make them continuation-kind reads (HOST verdict plus continuation that answers), which keeps the row ABAP under front-up. Also, git belongs to the STORE family, not to new SYSTEM kinds.
- source-read-objectstructure OUTLINE and checkruns CHECKRUN run a cold whole-tree abaplint registry parse (about 4 s after any write) inside the step. The FIFO rule forbids long work in the step. 'Node blocks the event loop too' does not hold under design B, where OData steps now queue behind it. Pre-warming after write and activation (store.warm) should be a precondition of these slices, not a later mitigation. abap-unit's PARSE UNIT_PLAN plus the xref risk graph is the same case.
- sessions-logoff-reentrance reentranceticket 400s as text/plain, and notebook refusals as JSON. Both break the stated rule that a refusal is a ZCX_OSD_ADT exception document, and ZIF_OSD_ADT_ROUTE's own contract that a route never writes an error body. Byte equality justifies them, but the rule needs an explicit, documented exception: either the route returns a non-2xx ty_response, or ZCX gets a plain-text or JSON rendering. Neither should be decided per slice.
- run-classrun COMMIT WORK fence before if_oo_adt_classrun~main, followed by ROLLBACK WORK on a dump. A route-level COMMIT/ROLLBACK inside the handler's step changes the handler's contract, which says session and handle rows are committed whatever the status. It also commits anything the handler did before the route. This must be specified in ZCL_OSD_ADT_HANDLER (for example a handler-provided fence), not done ad hoc by one route. The @KERNEL guard is a runtime seam, not host capability, but it also needs an explicit rule note.
- data-preview SQL inside the ADT step on STG_DB=duckdb. A failed statement can abort the step's transaction. Under front-up the same step also writes the session and CSRF rows (RESOLVE), so a refused SELECT could lose or 500 the session write and not only turn a 400 into a 500. Run the SQL in a savepoint or on a separate statement context, and test this before switching the rows, not after.
- write-includes 4a SYSTEM LOCK_OF reads req.adt.session. Under front-up the front fills req.adt from the ABAP verdict, so it keeps working, but it makes a host round trip for state ABAP already owns (ZOSD_ADT_SHDL plus ENQ). object-create-delete solves the same question natively (ZIF_OSD_ADT_SESSION, ENQ probe). Adding a new SYSTEM kind for 4a that front-up then makes redundant contradicts the sessions spec's 'no new kinds after front-up'. If 4a lands after front-up, use the session interface directly.
- editor-helpers-transport ABAP Unit motivation. It says the content_type literals must be pinned in ABAP Unit because 'the Node diff cannot see these, since Express's send() re-normalizes'. That is false for the Buffer replay (see inconsistencies). The diff does catch a non-normalized literal, so the extra Unit test is harmless, but the stated risk is wrong.
- data-preview's correction of port-map is right and port-map should be fixed. Port-map's claim that 'Running SQL is native: ADBC cl_sql_statement is in open-abap-core' would break byte equality: cl_sql_result_set copies only the first column, and get_metadata and next_package are ASSERT todo. Any family that relies on native ADBC must not.

## Shared infrastructure

- ZOSD_STORE IV_JSON parameter (fugr XML, Go host key list tools/gogen/go/abap/store.go, osd-store-destination givenText), plus ONE error envelope (EV_JSON {error:{code,message}}, raw message, no prefix). ZCL_OSD_ADT_HOST maps code -> ZCX factory: NOT_FOUND, CONFLICT, READ_ONLY, NOT_SUPPORTED, INVALID_NAME, INTERNAL. Remove the 'OBJECT x:' prefix from the existing wrappers in the same change, and update the LOCK diff test.
- Bound store by default. Every STORE command reads systemCalls.getStore()?.store ?? open(): READ, WRITE, CHECK, CHECKRUN, CREATE, DELETE, PACKAGE(S), SEARCH, PARSE, INACTIVE, VERDICT, COMPLETE. Today only READ, HISTORY, REVISION and OBJECT do, so the diff tests of 4a, checkruns, create-delete and information-system silently read the wrong tree.
- STORE READ extension (one change): EV_JSON {name, changedBy, empty, error:{code,message}}. STORE OBJECT extension (one change): package, packages chain, changedAt, changedBy, version, includes.
- STORE PARSE with kinds OUTLINE / DDLS / UNIT_PLAN (one dispatcher, one owner). Refactor tools/adt-cds.mjs, structureOf and runner.classes into exported functions that both Node routes and PARSE call.
- STORE PACKAGE (raw or local-view mode, subpackage descriptions, EV_JSON), PACKAGES (OBJECTS) and SEARCH. They are used by checkruns, information-system, nodestructure, packages/:name and vfs.
- ZIF_OSD_ADT_ROUTE=>TY_REQUEST extension, done once: session (ty_session: id, user, stateful), sessions REF TO zif_osd_adt_session, pattern (the matched row), uri (~request_uri). ZIF_OSD_ADT_SESSION~RELEASE_OBJECT. Handler: no RESOLVE/CSRF/stamp outside /sap/bc/adt (logoff), and Set-Cookie lines appended, not set, in the front replay.
- Front (tools/adt-abap-front.mjs) changes, done once: a 3xx and 201 replay rule (res.end with explicit Content-Length, no ETag); appending every Set-Cookie; an X-OSD-Miss marker (stripped, recorded in facade.missed) driven by a ZCX flag; a second mount for /sap/public/bc/icf/logoff; a query record with Express qs semantics (built from req.query, or a tolerant shim string_to_fields, since today's unescape_url throws on a stray '%' and '+' is not decoded).
- Continuation plumbing, done once on top of front-up: registration at module scope with per-request facade resolution (req.osdFacade = {store, options, step}); a generic resume entry ZCL_OSD_ADT_HANDLER=>RESUME( kind, json ) -> the route's resume method, used by activation FINISH, aunit render and the notebook run; preview and service-worker stubs for every kind.
- ZCL_OSD_ADT_URI: ENCODE_COMPONENT (moved out of ZCL_OSD_ADT_VERSIONS=>URI_NAME), DECODE_COMPONENT returning ok/failed (callers raise their own 400/500/transport refusal), and QUERY( name, found ) with qs semantics (repeated names joined with ',', absent vs empty).
- ZCL_OSD_ADT_ENTITY: TAG (sha256 UTF-8, first 32 lower-case hex), NORMALIZED (normalizedTag: trim, one W/, one quote at each end, no comma split), SEND (If-None-Match comma list, 200 type plus '; charset=utf-8', 304 with the bare type). Refactor ZCL_OSD_ADT_VERSIONS onto it, with its diff test as the guard. ZCX additions in the same change: MODIFIED (412), NOT_LOCKED (409 NotLocked), WRONG_DATA, NO_ACCESS(status), NOT_BUILT (503), TRANSPORT_CHECK_FAILED, plus a namespace parameter (com.sap.adt vs org.open-steamgate.osd).
- ZCL_OSD_ADT_TYPES=>ALL( ): the 15 TYPES rows in osd-store-types.mjs order, with collection, source flag, ADT_TYPE (plus the STRU fallback), label, plural, category and TREE_* labels, held equal to the JS tables by a mocha test. Plus OBJECT_FROM_URI (cut '#' and '?', strip /source/main, case-sensitive prefix over SOURCES) and TYPE_OF_COLLECTION. SOURCES( ) and LOCKABLE( ) are derived from ALL( ).
- Hand-written XML scanners (no FIND REGEX: 7.02 POSIX has no lazy quantifiers and no \b, and the transpiler hides that): ATTRIBUTE( xml, element, name ) with a JS \b-equivalent boundary, REFERENCES (every adtcore:uri), BLOCKS (<x ...>...</x>, first close), FIRST_TAG_VALUE. They are used by create-delete, 4a includeType, checkruns, activation, abap-unit, transport, nodestructure and vfs.
- Document builders shared across families: ZCL_OSD_ADT_CHECKREPORT (checkReportDocument with omitEmptyList, for checkruns and freestyle); ZCL_OSD_ADT_DOC_COMMON (namedItems, objectReferences, emptyFeed, exceptionDocument); ZCL_OSD_ADT_DDIC=>TABLE_FIELDS (owned by ddic B8, reused by data-preview C4, with the DTEL->DOMA resolver hook); a shared session-user-from-Basic helper.
- ZCL_OSD_ADT_JSON: an ordered writer whose string escaping equals JSON.stringify (\u00XX lower-hex controls, raw non-ASCII), replacing ZCL_OSD_ADT_SYSINFO=>JSON_STRING. It is used by unit/object, the notebook, introspection xref and entitysets. Also a SYSTEM 'raw' -> EV_SOURCE channel, so finished bodies skip ajson unescaping.
- ZCL_OSD_ADT_JS: NUMBER( ) (JS Number(), NaN flag), JS_INT (parseInt), GLOB (star-only), COLLATE key (ICU localeCompare approximation, checked against V8 in mocha), TRIM (Unicode whitespace including U+FEFF and NBSP). The rule that ABAP never re-sorts a host-ordered list belongs here as documentation.
- Store warm-up after write and activation (store.warm), as a precondition for in-step OUTLINE, CHECKRUN and PARSE UNIT_PLAN, so a cold registry parse never runs inside the step.
