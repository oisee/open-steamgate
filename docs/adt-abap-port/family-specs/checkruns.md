# checkruns

- Recommendation: **port-to-abap**
- Effort: M
- Owner: dell
- Depends on: front-up (slice 3: ABAP resolves session + CSRF so a POST row can be ABAP), PACKAGE store command (group B), at least name -> objects[] in host order, shared per-object check helper extracted from tools/adt-facade.mjs so the Node route and CHECKRUN cannot drift

## Routes

### GET `/sap/bc/adt/checkruns/reporters` (adt-facade.mjs ~2344)

200, Content-Type 'application/vnd.sap.adt.reporters+xml; charset=utf-8' (express res.send keeps/sets charset=utf-8), weak ETag W/"len-hash" generated by express from the body. Body is one line, no trailing newline: '<?xml version="1.0" encoding="utf-8"?><chkrun:checkReporters xmlns:chkrun="http://www.sap.com/adt/checkrun"><chkrun:reporter chkrun:name="abapCheckRun">' + one '<chkrun:supportedType>CODE*</chkrun:supportedType>' per key of TYPES (tools/osd-store-types.mjs) in declaration order: CLAS INTF PROG FUGR TABL DTEL DOMA TTYP DDLS SRVD VIEW SHLP MSAG DEVC INCL + '</chkrun:reporter></chkrun:checkReporters>'. No input read, no store call, no refusal. HEAD is answered by the router's GET-for-HEAD rule. Advertised in discovery as 'checkruns/reporters' (unchanged).

### POST `/sap/bc/adt/checkruns` (adt-facade.mjs ~2375)

Query (?reporters=abapCheckRun) is ignored. Body read raw (rawBody, any content type incl. application/*). Inside answered(): (1) checkObjectsIn(body, TYPES collections): for each regex block <chkrun:checkObject ATTRS>INNER</chkrun:checkObject> (lazy), uri = first adtcore:uri="..." in ATTRS (raw, NOT xml-unescaped), objectFromUri strips #fragment, ?query and a trailing /source/main, then matches the first collection prefix '/sap/bc/adt/<adt>/' in TYPES order (case-sensitive), name = decodeURIComponent(rest).toUpperCase() (a malformed %-escape throws URIError -> 500); unmatched blocks skipped; include = /includes/([^/]+)/ (needs a trailing slash) of the first chkrun:uri in INNER, else undefined; source = decodeContent(first <chkrun:content>...</chkrun:content>) or undefined when the element is absent (empty element -> "" which IS an overlay). decodeContent: trim; '' -> ''; plain = 5 entity decodes (&lt; &gt; &quot; &apos; then &amp; last; no numeric entities); if trimmed text matches /^[A-Za-z0-9+/\s]+={0,2}$/ then Buffer base64-decode (lenient) and use it only if it contains CR or LF and no U+FFFD, else plain. If no block matched at all: fallback objectReferencesIn = every adtcore:uri="..." anywhere in the body -> {type,name,uri: canonical uriOf(type,name) = /sap/bc/adt/<adt>/<encodeURIComponent(lower(name))>}, no source, no include. (2) packages: every /adtcore:uri="\/sap\/bc\/adt\/packages\/([^"]+)"/g in the whole body (case-sensitive, also inside checkObject blocks), decodeURIComponent (malformed -> 500). Per name: uri = /sap/bc/adt/packages/<encodeURIComponent(lower(name))>; store.package(upper(name)) -> push package report {uri, issues: []} then append each pkg.objects entry (host order = sort by type+name localeCompare) that has a TYPES adt as {type,name,uri canonical} to the END of objects; any throw -> {uri, status notProcessed, statusText 'package <name as decoded, original case> does not exist'}. Quirk to keep: a package URI ALSO maps to a DEVC object via checkObjectsIn, so a package check yields package report, then DEVC object report 'no dictionary check here; the object is present and readable', then the children. (3) objects empty AND package reports empty -> 400 'application/xml; charset=utf-8', exceptionDocument('ExceptionInvalidRequest','no check object in the request'). (4) reports = packageReports ++ objects.map: non-source type -> store.read(type,name) ok -> {issues:[], statusText 'no dictionary check here; the object is present and readable'} / throw -> {status notProcessed, statusText e.message}; source type -> store.check(type,name,{source, include}) issues (abaplint, severity E, line/column from issue start; DDLS adds ddlsIssues first) ++ for CLAS with include undefined or 'main' and a source (inline, else store.read(CLAS).source) portabilityWarnings(source, '<lower name>.clas.abap', store, engine) where engine = STG_DB (default sqlite; file/memory/sqljs -> sqlite), severity W, only for sqlite/duckdb/postgres and BY DATABASE PROCEDURE|FUNCTION; any throw -> {status notProcessed, statusText message}. (5) 200, Content-Type 'application/vnd.sap.adt.checkmessages+xml; charset=utf-8', express weak ETag, body = checkReportDocument(reports) WITHOUT omitEmptyList: '<?xml version="1.0" encoding="utf-8"?>\n<chkrun:checkRunReports xmlns:chkrun="http://www.sap.com/adt/checkrun">\n' + reports joined by '\n' + '\n</chkrun:checkRunReports>\n'; each report '  <chkrun:checkReport chkrun:reporter="abapCheckRun" chkrun:triggeringUri="ESC(uri)" chkrun:status="ESC(status??processed)" chkrun:statusText="ESC(statusText ?? (n==0 ? 'no errors' : n+' error(s)'))">\n    <chkrun:checkMessageList>\n' + messages joined '\n' + '\n    </chkrun:checkMessageList>\n  </chkrun:checkReport>' (an empty list still has the empty line between open and close tags); message '      <chkrun:checkMessage chkrun:uri="ESC(uri)#start=LINE,COL" chkrun:type="ESC(severity??E)" chkrun:shortText="ESC(message)"/>' with line??1, column??1. ESC escapes & < > " only (not '), same as ZCL_OSD_ADT_XML=>esc. 'n error(s)' counts warnings too. Any other throw inside answered -> 500 ExceptionInternalError, namespace org.open-steamgate.osd (e.g. 'URI malformed').

## Host dependencies

- Abaplint check of one object with an optional inline overlay: EXISTING store command CHECK (osd-store-destination.mjs #check) is NOT sufficient: (a) ET_ISSUE rows (ZOSD_ISSUE_S: OBJ_TYPE OBJ_NAME LINE COL RULE MESSAGE) carry no SEVERITY, so the portability W cannot be told from E; (b) it does not append portabilityWarnings nor know the engine; (c) it uses this.store (the destination's own opened store), not the facade instance's bound store (systemCalls.getStore().store) like READ/HISTORY/OBJECT do, so a diff test with a per-facade ObjectStore checks the wrong tree; (d) an absent IV_SOURCE and an empty one cannot be told apart from ABAP, but Node treats <chkrun:content></chkrun:content> as an empty overlay.
- NEW store command CHECKRUN (one object; leaves CHECK untouched for the webgui screen, which reads EV_ACTIVE/EV_COUNT and would change meaning if warnings were added): IV_COMMAND='CHECKRUN', IV_TYPE, IV_NAME, IV_INCLUDE ('' = undefined, i.e. main), IV_SOURCE, IV_FILTER='SOURCE' when the request carried a content element (even empty) else ''. Runs on the bound store the exact per-object branch of the facade (non-source -> store.read presence; source -> store.check + portabilityWarnings for CLAS main with engine from STG_DB normalised) and answers EV_JSON = {"status":"processed"|"notProcessed","statusText":<string, omitted when default>,"issues":[{"severity":"E|W","line":n,"column":n,"message":"..."}]} with line/column/severity already defaulted (??1, ??E) by the host so ABAP never re-derives them; thrown errors become status notProcessed + statusText String(e.message), exactly as the facade catches them. Best implemented by extracting the facade's per-object lambda into one exported function (e.g. checkRunReport(store, o, engine) in tools/adt-documents.mjs or a new tools/adt-checkrun.mjs) that both the Node route and the destination call, so the two cannot drift. Add CHECKRUN to COMMANDS and CAPABILITIES.
- Package expansion: NEW store command PACKAGE (already planned in port-map section 3 for group B; not on origin/main yet: COMMANDS = LIST READ WRITE CHECK ACTIVATE CAPABILITIES HISTORY REVISION, plus OBJECT/SYSTEM). This route needs only IV_NAME -> EV_ERROR on any failure (ABAP ignores the text and writes 'package <name> does not exist'), else ET_OBJECT rows (TYPE, NAME) in store.package(...).objects order (localeCompare sort done by the host; ABAP must NOT re-sort, ABAP SORT is binary and differs). If B's PACKAGE is late, a minimal PACKAGE returning just the object list is the stop-gap; B extends it later (subpackages with descriptions).
- No SYSTEM kind needed: session and CSRF are the front's (slice 3, design B). Existing SYSTEM kinds (IDENTITY LOCK_HANDLE LOCK_RELEASE SESSION LOCK_HOLDER) are untouched.
- DB engine (STG_DB) is read host-side inside CHECKRUN; nothing to pass from ABAP. The port-map's CAPABILITIES db_engine extension is not required for this family.

## Rationale

Both routes are pure request/response with no generation rebuild or swap, so neither needs a host continuation. GET reporters is a constant document built from TYPES and ports trivially. POST checkruns splits cleanly: the analysis (abaplint over an inline overlay, the DDLS generator check, AMDP portability lowering) is host state and cannot run in ABAP. There is no ABAP parser in src/, and the registry lives in the host. Everything else can be ported: body parsing, base64/entity decoding, URI to object mapping, package expansion order, the 400 refusal, the DEVC quirk, and the whole checkRunReports document. So ABAP owns the protocol, and the host answers one object at a time through a new CHECKRUN store command, plus the PACKAGE command that B is adding. A run can hold the work process for as long as abaplint takes: a cold registry parse after an activation, or a package with many objects. That costs no more than the Node event loop already blocking on the synchronous store.check, and it is not a rebuild or a swap, so it stays inside the step. The ABAP document builder (checkReportDocument with omitEmptyList) is also what C4 datapreview/freestyle needs for its SQL check report, so building it here pays twice.

## ABAP design

Classes: ZCL_OSD_ADT_CHECK_REPORTERS (GET) and ZCL_OSD_ADT_CHECKRUN (POST), both implementing ZIF_OSD_ADT_ROUTE, plus ZCL_OSD_ADT_CHECK_DOC, the document builder: method report_document( it_reports, iv_omit_empty_list ) mirroring checkReportDocument byte for byte, including the '\n' joins and the empty line inside an empty checkMessageList. The newline is cl_abap_char_utilities=>newline, never a backtick literal with \n. Router rows: two literal rows, 'GET /sap/bc/adt/checkruns/reporters' -> ZCL_OSD_ADT_CHECK_REPORTERS (HEAD through the GET rule) and 'POST /sap/bc/adt/checkruns' -> ZCL_OSD_ADT_CHECKRUN. They are placed before the HOST catch-all, and the reporters row before any pattern that could shadow it. ZCL_OSD_ADT_TYPES gains all( ): the 15 TYPES entries in osd-store-types.mjs order (CLAS INTF PROG FUGR TABL DTEL DOMA TTYP DDLS SRVD VIEW SHLP MSAG DEVC INCL) with collection and a source flag. sources( ) and lockable( ) stay as they are, and a unit test checks that all( ) equals TYPES. That test is generated or compared in mocha against the JS object, so a new type cannot drift. Reporters: loop over all( ) and concatenate the one-line XML. Content type 'application/vnd.sap.adt.reporters+xml; charset=utf-8'. POST steps: (1) convert the body xstring to string as UTF-8. (2) Scan <chkrun:checkObject blocks with FIND/SEARCH and offsets, not regex. A lazy '[\s\S]*?' is PCRE-only and does not exist on 7.02 POSIX REGEX, so a hand scanner matches the JS semantics: the first '</chkrun:checkObject>' after the open tag's '>'. Inside a block: the first adtcore:uri="..." in the attribute part, the first chkrun:uri="..." in the inner part, and the first <chkrun:content>...</chkrun:content>, with presence tracked separately from emptiness. (3) object_from_uri: cut at '#' and '?', strip a trailing '/source/main', then prefix-match '/sap/bc/adt/<collection>/' over all( ) in order, case-sensitive. Decode with a checkruns variant of ZCL_OSD_ADT_URI=>decode_segment that raises zcx_osd_adt=>internal( 'URI malformed' ) (status 500, namespace org.open-steamgate.osd, matching Node's URIError through answered()) and not the 400 'Failed to decode param' of the router, then to_upper. (4) decode_content: trim, then decode the 5 entities with &amp; last. If the text CO the base64 alphabet plus whitespace with at most two trailing '=', decode the base64 leniently: strip whitespace and tolerate a missing pad, because Node's Buffer does. Convert to a string strictly as UTF-8. Use the decoded text only if it has CR or LF and the conversion raised no codepage error. That error stands in for U+FFFD, so the decoded text is used when there is no error, and the plain text otherwise. (5) If no block matched, fall back to every adtcore:uri in the body, with a canonical uri built by a new ZCL_OSD_ADT_URI=>encode_component that implements exactly the encodeURIComponent unreserved set A-Z a-z 0-9 - _ . ! ~ * ' ( ). It must not use cl_http_utility, whose set differs ($ / etc.). (6) Package pass over every 'adtcore:uri="/sap/bc/adt/packages/' occurrence in the whole body. Per name, call host PACKAGE, build the package report, and append the child objects at the end of the objects table in host order. (7) If both tables are empty, raise zcx_osd_adt=>invalid_request( 'no check object in the request' ), which gives 400 and application/xml; charset=utf-8. (8) Per object, one host call: ZCL_OSD_ADT_HOST=>checkrun( iv_type iv_name iv_include iv_source iv_has_source ) -> ty_check_report (status, status_text, issues[] severity/line/column/message), parsed with zcl_ajson like identity( ). A host EV_ERROR (transport failure, unknown command) is internal 500, which is distinct from a per-object notProcessed that comes back inside EV_JSON. (9) Build the document and answer 200 with 'application/vnd.sap.adt.checkmessages+xml; charset=utf-8'. The ETag stays express's job in the front, as for versions and lock. The host is asked only for analysis and the package list. The host finishes nothing after the step, so there is no continuation.

(9) An unknown package gives notProcessed 'package zzz does not exist' with the original-case name. (10) A legacy body with no checkObject blocks, only adtcore:objectReference entries, gives the canonical uris. (11) '<chkrun:checkObjectList/>' gives 400 ExceptionInvalidRequest. (13) Base64 lookalike plain text with no punctuation (e.g. 'REPORT ztest') falls back to plain. Base64 of non-UTF-8 bytes falls back to plain. Base64 with embedded newlines and missing padding decodes. (14) A uri carrying '&amp;' or '\"' is echoed re-escaped the same way. (15) A message with a non-ASCII character keeps the same UTF-8 bytes. Red proof: break one join (e.g. drop the empty line in an empty checkMessageList) and show the gate fails. Point the ABAP row back to HOST and show the 'served by ABAP' assertion fails. Run test/adt-devloop.mjs (:278-398), test/adt-facade.mjs :444 and test/adt-notebook.mjs :84-92 with the front on. ## Risks

- Byte-equality depends on the host's issue text and order, which comes from abaplint and so is non-deterministic only if the registry is. Both paths call the same store, so equal by construction; but CHECK today reads the destination's own store, not the facade-bound one -- CHECKRUN must use systemCalls.getStore().store or the diff test checks two different trees.
- store.check mutates the shared abaplint registry (#withSource swaps a file and reparses, restoring in finally). It is synchronous in Node; through the destination it must stay synchronous between swap and restore (no await inside), or a concurrent request sees the overlay.
- Long checks hold the work-process: a cold registry() parse after activation invalidated it, or a package with hundreds of source objects (N CHECKRUN round trips). Not a rebuild/swap, so allowed in-step, but a big package check now queues every other ABAP request behind it (FIFO). Mitigation if measured bad: a batch form of CHECKRUN (IV_FILTER list or JSON in IV_SOURCE) -- keep the per-object form first.
- Regex semantics: Node uses lazy JS regexes; 7.02 POSIX REGEX has no lazy quantifier, and the transpiler mapping JS regex would pass here and fail on a real system. Hand scanner required, and its edge semantics (first close tag, first attribute) must be tested, not assumed.
- decodeContent edge semantics: Node's Buffer base64 is lenient (ignores invalid tail, missing padding) and the U+FFFD test is about lossy UTF-8 decoding; ABAP's decode_base64 / cl_abap_conv_in_ce may raise where Node succeeds (or vice versa) -- verify open-abap-core's implementations of both on the transpiler before relying on them (CLAUDE.md: no CL_* is assumed complete).
- encodeURIComponent and decodeURIComponent need exact ABAP twins; cl_http_utility escape sets differ. decode_segment exists but refuses with 400, the checkruns path must answer 500 'URI malformed' like Node's URIError via answered().
- The DEVC duplicate report for a package URI is a Node quirk that a 'cleanup' would break byte-equality; keep it and note it in ANORMALIES only if a client complains.
- PACKAGE is group B's new command and not on main yet; this family depends on at least its object-list half.
- Messages may in principle carry host paths (portability errors quote compiler messages); Node does not strip them, so equality holds, but it is an existing leak surface worth a withoutHostPaths pass in the shared helper (would change both sides together).
