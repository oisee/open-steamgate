# run-classrun-notebook

- Recommendation: **abap-protocol-plus-host-continuation**
- Effort: L
- Owner: dell (group C per port-map: C5 classrun now, C6 notebook after stoker's 4b continuation)
- Depends on: front-up (slice-3 design B) only for the COMMIT fence semantics; classrun itself can land in the mixed phase, 4b (activation continuation mechanism) before the notebook slice, Node-side NOT_BUILT fix in tools/osd-classrun.mjs (same slice as classrun)

## Routes

### POST `/sap/bc/adt/oo/classrun/:name` (adt-facade.mjs ~1947)

Drains the body (ignored; ?profilerId ignored). store.classrun() -> ClassRun#run(name,{data}): store.find('CLAS', name) undefined -> NotFound -> record(req,'object',msg) into facade.missed + refuse 404 ExceptionResourceNotFound (com.sap.adt) 'CLAS <name as given in the path, not upper-cased> does not exist'. Source of entry.name read from the store and matched with /^\s*INTERFACES\s+if_oo_adt_classrun\b/im; no match -> NotClassrun -> 400 ExceptionInvalidRequest '<ENTRY.NAME> does not implement IF_OO_ADT_CLASSRUN'. Child mode (data.runtime set) forwards to the child's POST /osd/classrun (JSON {name}); inline: no output/init.mjs -> NOT_TRANSPILED 503 ExceptionInternalError (com.sap.adt) 'there is no output/ yet: ...'; boots Data only if no DEFAULT connection; runClassrun imports output/<name>.clas.mjs (importFresh, 500 ms ENOENT retry), re-checks Local.IMPLEMENTED_INTERFACES includes IF_OO_ADT_CLASSRUN (400 again), imports ZCL_OSD_CLASSRUN_OUT (missing -> NOT_TRANSPILED 503), then ONE dialogStep('classrun NAME'): new OUT, new class, if_oo_adt_classrun~main(out), text = out->text(); commit on success. Any throw inside (ABAP cx OR plain JS error such as ASSERT/todo) -> rollback, dumpOf(error) {name=constructor.name upper, message=error.message.get?() ?? message, where=describe() via source maps 'CX_SY_ZERODIVIDE at zcl_x.clas.abap:12  <statement>' or 'NAME (no ABAP position; is write_source_map on?)', frames}, persistDump fire-and-forget as its OWN later dialogStep (row: dump_id random, created_at now, req_method 'classrun', req_path NAME, generation '0' on the inline facade path, cap delete), partial text read back from OUT. Answer always 200 'text/plain; charset=utf-8' (express adds Content-Length and weak ETag) with body = text, or text + ('\n\n' if text non-empty) + 'Runtime error: <message> at <where>'. Module import failure for a class whose source exists but was never built -> generic 500 ExceptionInternalError org.open-steamgate.osd with the Node error message (contains an absolute host path). NOT_SUPPORTED/NOT_BUILT codes are mapped to 503 but nothing on this path throws them today.

### POST `/sap/bc/adt/notebook/abap` (adt-facade.mjs ~1979)

Body must be JSON (JSON.parse of the raw UTF-8); parse failure -> 400 application/json {"error":{"code":"BAD_REQUEST","message":"a JSON body with source is required"}}; source not a string or blank after trim -> 400 {.."notebook ABAP source is empty"}. NOT the ADT exception document: every answer of this route is res.json (application/json; charset=utf-8, ETag). Then serialized on a process-wide promise chain notebookCellRun (one cell at a time per facade instance): scratch root = store.roots entry pack 'notebook-scratch' writable, else 503 NOTEBOOK_SCRATCH_MISSING 'the notebook-scratch pack is not configured; start osd through the VS Code launcher'. Fixed class ZCL_OSD_NOTEBOOK_CELL: remember previous source + whether it was active; store.write(CLAS, name, source, 'main', {root: scratch}); checked = store.warmActivation; store.publish({activate:[CLAS name]}) (a BUILD + generation swap/hot swap); activation.ok===false -> first transpile issue message (or activation.error / transpile.output / fallback text) -> 422 NOTEBOOK_ACTIVATION_FAILED; on any failure the previous source is restored into the scratch root (or the class deleted if new) and, if it was active, completeActivation(warmActivation) restores its ADT state; completeActivation(checked, built) false -> 422 'source changed during activation; run the notebook cell again'. Then the same classrun as above (store.classrun().run(name,{data})) and 200 JSON {text, ok, ms, generation} where text uses the same 'Runtime error:' suffix, ms is wall time, and generation is ALWAYS absent (runClassrun never returns it, so JSON.stringify drops the key). Anything else -> 500 {error:{code: e.code ?? 'FAILED', message}}; a NotFound/NOT_CLASSRUN from the classrun (e.g. cell source without INTERFACES if_oo_adt_classrun) also lands as 500 with that code.

## Host dependencies

- STORE OBJECT (exists): CLAS <name> -> {found, type, name, writable}; gives the 404 and the canonical entry.name. Already wrapped by ZCL_OSD_ADT_HOST=>OBJECT; reads the per-facade bound store (withSystem), as Node's store.find does.
- STORE READ (exists): CLAS <ENTRY.NAME> include main -> EV_SOURCE; for the regex INTERFACES check that decides the 400 exactly as Node does (source-based, inactive source included). Needs a small ZCL_OSD_ADT_HOST=>READ wrapper if slice 4a has not added one; READ also uses the bound store.
- NEW SYSTEM kind DUMP: IV_NAME = JSON {name, message, stack, request:'classrun <NAME>'} -> EV_JSON {where, frames}; the host runs abapFrames(stack string)/describe-equivalent from tools/osd-where.mjs (it already accepts a stack string) so the 'Runtime error: ... at <where>' line is byte-equal, and queues persistDump(connection, dump, {request, generation:'0'}) WITHOUT awaiting it (it is its own dialogStep, which must run after the current one, exactly as Node's fire-and-forget does). Added to SYSTEM_KINDS in tools/osd-store-destination.mjs and answered by the facade's withSystem binding (adt-facade.mjs system answers). On a real system: no destination -> ABAP falls back to CX get_source_position for where and writes nothing to ZOSD_DUMP (a system has ST22).
- NEW kernel helper (not a host command, an @KERNEL class like src/osd/git/zcl_abapgit_zlib): ZCL_OSD_KERNEL_GUARD=>CALL_CLASSRUN( io_run io_out ) EXPORTING ev_failed ev_name ev_message ev_stack -- WRITE '@KERNEL try { ... } catch (e) { ... }' around if_oo_adt_classrun~main, so both ABAP exceptions and plain JS runtime errors (ASSERT 1 = 'todo', TypeError) are caught the way runClassrun's dialogStep catch does; name = constructor.name upper, message = e.message?.get?.() ?? e.message, stack = String(e.stack). On a system the @KERNEL lines are comments and it is a plain call (a dump there is a short dump).
- CAPABILITIES (exists, no change needed): NOT_TRANSPILED/'output/ missing' is unreachable from ABAP (the handler is itself transpiled output); no 'built?' capability is required, contrary to port-map row C5.
- Notebook only -- NEW host continuation kind NOTEBOOK_CELL (rides the continuation mechanism slice 4b introduces for activation; does not exist on main yet: grep finds no 'continuation' in src/adt or tools/adt-abap-front.mjs): payload {source}; the host does, after the step and on the notebookCellRun chain, scratch-root lookup, store.write with {root}, warmActivation, publish, rollback-to-previous on failure, completeActivation -- this is host fs/build/generation state and must not run inside a dialog step (publish rebuilds and hot-swaps the module graph the handler runs in, ~0.46 s warm / ~18 s cold, and holds the FIFO).
- Notebook only -- the run step after the continuation: the host enters a SECOND dialog step and calls ZCL_OSD_ADT_CLASSRUN=>RUN( 'ZCL_OSD_NOTEBOOK_CELL' ) (the same ABAP as the classrun route, now resolving the hot-swapped class through abap.Classes), then ABAP shapes the {text, ok, ms} JSON; ms is measured in ABAP (GET RUN TIME) or by the host around the step.
- STORE WRITE with a root (port-map section 3 note) and ACTIVATE-with-rollback are NOT needed if NOTEBOOK_CELL is one host continuation; they would be needed only if the notebook transaction were driven from ABAP, which it should not be.

## Rationale

The two routes split differently. oo/classrun is a full port. Running a class is exactly what a dialog step is for, and Node already runs it as one dialog step (runClassrun -> dialogStep), so moving it into the handler's step changes nothing about the work-process FIFO. A classrun that runs long or WAITs holds or yields the work process the same way today. Inline (the only mode where the ABAP front is mounted, test/start.mjs MODE==='inline'), ABAP's CREATE OBJECT TYPE (name) resolves through abap.Classes. That is the table the hot swap (tools/osd-hot.mjs) updates, so the ABAP route runs the class the current generation serves. It is more correct than Node's importFresh of output/<name>.clas.mjs, which osd-classrun.mjs's own header admits can bind a stale module graph in a still-running inline process. The 404/400 decisions come from existing STORE commands (OBJECT, READ) with the same source regex. The 400 re-check against IMPLEMENTED_INTERFACES is available through RTTI in open-abap-core (cl_abap_objectdescr fills INTERFACES from IMPLEMENTED_INTERFACES, the same field runClassrun reads). The output capture already lives in ABAP (ZCL_OSD_CLASSRUN_OUT keeps text in object memory, so it survives a ROLLBACK WORK). The only things ABAP cannot do alone are catching a non-class-based JS runtime error and producing the source-mapped 'where' line. Those two make the dump text byte-equal, and they become one small @KERNEL guard plus one SYSTEM kind (DUMP). notebook/abap cannot be ported whole. Its core is write-to-scratch-pack plus publish plus rollback-on-failure plus completeActivation, which rebuilds and swaps the generation the handler itself runs in. The milestone rules forbid that inside a step, so it is a host continuation. Everything around it can be ABAP: body validation, the JSON error shapes, the serialization verdict, and above all the run itself, done as a second ABAP step through the same ZCL_OSD_ADT_CLASSRUN=>RUN. The route row then becomes ABAP (not HOST), which the done-criterion needs. This reverses port-map C6's 'keep served-by HOST' recommendation, and that reversal is only safe once 4b's continuation mechanism exists. Owner: port-map already puts both in group C, so dell. Classrun (C5) can start now. The notebook (C6) lands after stoker's slice 4b defines the continuation and the activation host path; it should reuse 4b's publish continuation and not invent a second one.

## ABAP design

Router rows (zcl_osd_adt_router=>routes, before the HOST catch-all; neither collides with the lockable 'POST <collection>/:name' rows because oo/classrun and notebook are not type collections): add( POST `/sap/bc/adt/oo/classrun/:name` ZCL_OSD_ADT_CLASSRUN ) and add( POST `/sap/bc/adt/notebook/abap` ZCL_OSD_ADT_NOTEBOOK ). These are not per type, so they are written by hand and not generated from ZCL_OSD_ADT_TYPES.

ZCL_OSD_ADT_CLASSRUN (implements ZIF_OSD_ADT_ROUTE, ~200 lines):
 handle: lv_name = param 'name' (already percent-decoded by dispatch, like Express req.params).
  1. ls_obj = zcl_osd_adt_host=>object( iv_type = `CLAS` iv_name = to_upper( lv_name ) ). If not found, RAISE zcx_osd_adt=>not_found( |CLAS { lv_name } does not exist| ), with the path name as given and not upper-cased, because Node's NotFound uses req.params.name.
  2. Read the source with STORE READ CLAS ls_obj-name main. SPLIT it at newline and run FIND FIRST OCCURRENCE OF REGEX `^\s*INTERFACES\s+if_oo_adt_classrun\b` IN TABLE ... IGNORING CASE. If nothing matches, raise invalid_request( |{ ls_obj-name } does not implement IF_OO_ADT_CLASSRUN| ).
  3. rs_response = run( ls_obj-name ), with status 200, content_type `text/plain; charset=utf-8` and body text.
 CLASS-METHOD run( iv_name ) RETURNING ty_run {text, ok, where, message} RAISING zcx_osd_adt, public so the notebook's second step reuses it:
  a. Check the class with cl_abap_typedescr=>describe_by_name( iv_name ) EXCEPTIONS type_not_found. If it is not found (the source exists but was never built in this generation), raise a NEW 503 refusal, zcx_osd_adt=>not_built( |{ iv_name } is not built: activate it first| ) with ExceptionInternalError and com.sap.adt. Node must be changed in the same slice to throw NOT_BUILT before importFresh, so the two sides agree; today Node answers 500 with an absolute host path, which no diff can hold. Then check the INTERFACES table of the cl_abap_classdescr for IF_OO_ADT_CLASSRUN, which mirrors runClassrun's IMPLEMENTED_INTERFACES check and gives the same 400.
  b. COMMIT WORK as a fence. This is a no-op in the mixed phase. Under slice-3 design B the session row touched by RESOLVE must not be lost to the rollback below, which is port-map risk 1.
  c. CREATE OBJECT lo_out TYPE zcl_osd_classrun_out. CREATE OBJECT lo_run TYPE (iv_name).
  d. zcl_osd_kernel_guard=>call_classrun( io_run = lo_run io_out = lo_out IMPORTING ev_failed ev_name ev_message ev_stack ).
  e. On success: text = lo_out->text( ), ok = true. The handler's step commits, as Node's dialogStep does.
  f. On ev_failed:
   - ROLLBACK WORK.
   - lv_json = zcl_osd_adt_host=>system( iv_kind = `DUMP` iv_name = json{name,message,stack,request:'classrun '&&iv_name} ) and take where from it. If the host is absent (a real system), build where from cx get_source_position.
   - text = lo_out->text( ). If it is non-empty, append newline newline. Append `Runtime error: ` && message && ` at ` && where. Use cl_abap_char_utilities=>newline, never a literal \n.
   - ok = false.
 The answer is not refused, so the front replays it with res.send and Express computes the same ETag as Node's .type().send().

ZCL_OSD_KERNEL_GUARD (new, src/adt or src/classrun, ~40 lines, 7.02 + ASCII): one class-method whose body is WRITE '@KERNEL try { await io_run.get().if_oo_adt_classrun$main({out: io_out.get()}); } catch (e) { ev_failed.set("X"); ev_name.set(...upper constructor name...); ev_message.set(String(e?.message?.get?.() ?? e?.message ?? e ?? "")); ev_stack.set(String(e?.stack ?? "")); }'. The plain ABAP fallback line is a normal call. Check the interface-method JS name against the transpiled zcl_osd_classrun_out and the demo class before relying on it.

ZCL_OSD_ADT_NOTEBOOK (slice 2 of this family, after 4b):
 Step 1, ABAP:
  - Parse the body with zcl_ajson.
   - If parsing fails, answer 400 with application/json; charset=utf-8 and body {"error":{"code":"BAD_REQUEST","message":"a JSON body with source is required"}}. This is a plain response and not a ZCX refusal, because the client is the VS Code notebook and Node answers JSON here. It needs a documented exception to the 'refusal = exception document' rule, or a ZCX variant that renders JSON.
   - If /source is not a string or is blank after condense, answer the 'notebook ABAP source is empty' 400.
  - Otherwise return the continuation verdict NOTEBOOK_CELL {source}.
 The host, on the notebookCellRun chain, does scratch lookup, write, warmActivation, publish, rollback-on-failure and completeActivation. A host failure maps to 503 NOTEBOOK_SCRATCH_MISSING, 422 NOTEBOOK_ACTIVATION_FAILED or 500, written by the host in Node's exact JSON. The host then opens step 2.
 Step 2, ABAP: zcl_osd_adt_classrun=>run( `ZCL_OSD_NOTEBOOK_CELL` ), with the JSON {"text":...,"ok":true|false,"ms":N} written in this key order, ms measured around the run, and no generation key. A ZCX from run( ) is answered as 500 {error:{code,message}} with code NOT_FOUND or NOT_CLASSRUN, as Node does today.

Front changes:
 (1) Express records a 404 from an ABAP row into facade.missed. Without it the 'not-served' report loses classrun misses that Node's record(req,'object',...) adds. This is generic and helps every ported route.
 (2) The continuation hook from 4b gains a second ABAP step after the host work.

## Test plan

Extend test/adt-abap-diff.mjs (two adtRouters over one store, the ABAP side via abapRunner/dialogStep, served-by asserted ABAP). Compare status, content-type, Content-Length, ETag and body bytes. Cases for oo/classrun:
 (1) ZCL_OSD_CLASSRUN_DEMO: 200, text/plain; charset=utf-8, 'hello from classrun' body byte-equal.
 (2) The same name in lower case and %-encoded, which exercises the Express-equivalent case-insensitive path plus decoding.
 (3) ZCL_NOT_A_THING_AT_ALL and a lower-case unknown name: 404 exception document, with the message preserving the path's case.
 (4) A class without the INTERFACES line (the SCRATCH fixture from adt-devloop Q6b): 400 ExceptionInvalidRequest, message with the canonical upper name.
 (5) A class whose INTERFACES line is indented or mixed-case, and one that only inherits the interface from a superclass. Both sides answer 400, because the regex is source-only.
 (6) ZCL_OSD_CLASSRUN_DUMPER: 200 body 'before the dump\n\nRuntime error: <msg> at <where>' byte-equal. This holds because DUMP maps the same stack string through osd-where. Also assert a ZOSD_DUMP row with objname ZCL_OSD_CLASSRUN_DUMPER and runtime_error containing ZERODIVIDE, and that rows the dumper INSERTed before the dump are absent on both sides (rollback).
 (7) A fixture that dumps on its first statement (empty partial text, so no blank-line prefix).
 (8) A fixture that hits a non-class-based JS error, e.g. a call into an open-abap-core 'ASSERT 1 = todo' method: Node 200 + 'Runtime error:'. This is the case that proves the kernel guard. Without the guard ABAP answers 500, which is the red proof.
 (9) A class that writes nothing: 200 empty text/plain. Check the ETag/Content-Length of an empty typed send on both sides.
 (10) Non-ASCII output (a WRITE of 'Grüße' built with cl_abap_conv) to hold the UTF-8 bytes through the shim's set_cdata.
 (11) A table and a structure WRITE (ZCL_OSD_CLASSRUN_OUT formatting is shared code, so equal by construction, but pinned anyway).
 (12) A class whose source exists in the store but is not in the generation: both sides 503 NOT_BUILT after the paired Node fix. Before that fix, mark it a known divergence.
 (13) A body sent with the POST and ?profilerId=x: both are ignored.
 (14) GET on the classrun path still falls to HOST (catch-all) on both sides.
 A classrun with DB side effects runs twice in the diff (once per side), so the fixtures are read-only or the test reads counts relative to before.

Cases for notebook/abap, after 4b: bodies of non-JSON, '[]', '"x"', '{"source":1}', '{"source":"   "}', each giving byte-equal 400 JSON. Watch JSON.parse versus zcl_ajson on a top-level scalar or array, and on a UTF-8 BOM. A store double without the scratch root gives 503. A cell with a syntax error gives 422 plus the scratch file restored to the previous source. A good cell gives 200 JSON byte-equal after replacing the "ms":\d+ value. A cell without INTERFACES gives 500 NOT_CLASSRUN JSON. Two concurrent cells are serialized (the second sees the first's class only after it completed). test/adt-notebook.mjs (store double, event order write/check/publish/complete/classrun) must stay green, with the classrun event now coming from the ABAP step.

Keep the ABAP-FS conformance run (--start) at 29 PASS / 2 FAIL / 16 MISSING or better, plus adt-devloop Q6b (5 cases) and the notebook (4) through the front.

Red proof: (a) with the kernel guard replaced by a plain call, case 8 fails; (b) with the COMMIT/ROLLBACK fence removed, the half-written-row assertion of case 6 fails; (c) with the 404 name upper-cased, case 3 fails; (d) with the router row removed, the served-by assertion fails.

ABAP Unit on ZCL_OSD_ADT_CLASSRUN for the regex decision (indent, case, comment line '* INTERFACES if_oo_adt_classrun', 'INTERFACES if_oo_adt_classrun_out' must NOT match because of \b vs _). Note that \b treats '_' as a word character, so 'if_oo_adt_classrun_out' does not match in JS either. Pin it on both sides.

## Risks

- Byte-equality of the dump line: 'where' is source-map output (tools/osd-where.mjs: basename of the ABAP file, line, trimmed statement text) and is only computable by the host. Without the SYSTEM DUMP kind, ABAP's get_source_position gives a different file and line format. The kind must receive the very JS stack string of the caught error, so the kernel guard has to capture e.stack before anything rethrows.
- Non-class-based errors (plain JS throws from open-abap-core stubs, TypeErrors) are not catchable by CATCH cx_root. Without the @KERNEL guard they escape the handler's step, the front answers 500, and Node answers 200 + 'Runtime error:'. The guard is a kernel seam, so the agreed rule 'host capability only via STORE/SYSTEM' needs an explicit note that a runtime guard is not host capability (precedent: zcl_abapgit_zlib @KERNEL try/catch).
- The rollback inside the ADT step: once the session moves into ZOSD_ADT_SESS (slice-3 design B), a ROLLBACK WORK after a dump would also undo RESOLVE's session touch and handle writes. The route must COMMIT WORK before calling main. That fence also commits anything the handler did earlier in the step, which is fine for the routes that exist today but has to be stated in the handler's contract.
- The dump row: Node persists via persistDump in its own later dialogStep (fire-and-forget). If SYSTEM DUMP awaited that inside the ABAP step, it would deadlock or throw 'nested dialog step'. It must be queued and not awaited. Generation is '0' on the facade path on both sides; improving that is a separate change to both sides.
- Process and generation: the ABAP front runs only inline. Child mode (STG_SERVE=child) keeps the Node route and the /osd/classrun door in the child, so the HOST-row-free goal holds only for inline until the front moves into child mode (slice-3 open question). If the front later sits in the parent, a classrun must execute in the process holding the generation, which brings back the forwarding problem.
- Divergence that exists today: a class whose source is in the store but not built. Node gives a 500 with an absolute host path, which is also a public-repo leak concern in logs and captures. ABAP gives cx_sy_create_object_error or the describe_by_name failure. Fix Node to a 503 NOT_BUILT in the same slice, or the diff cannot be green.
- Regex parity: JS /^\s*INTERFACES\s+if_oo_adt_classrun\b/im versus ABAP POSIX/PCRE through the transpiler. Check that \b and ^ under IN TABLE behave identically for CRLF sources (a trailing \r on a line) and for tabs.
- The notebook violates the 'refusal = ADT exception document' rule by design: its client expects JSON {error:{code,message}}. Either the rule gets an explicit exception for this route, or ZCX needs a JSON rendering. Decide this before slice 2.
- The notebook continuation does not exist yet: no 'continuation' appears in src/adt or tools/adt-abap-front.mjs on origin/main. It needs 4b's mechanism plus a second ABAP step after the host work, which 4b may not need (activation answers from host state). If 4b's design does not allow a follow-up step, the notebook row stays HOST and the done-criterion is missed for it.
- The notebook ms field is wall time and can never be byte-equal. The diff normalizes it, and that normalization must be the only one.
- Long or looping classruns hold the work-process FIFO in both implementations. The port does not make this worse, but once the front moves up (design B) every delegated ADT request queues behind a running classrun, which it does not do today because the Node route enters its step only for the run itself.
