## Routes

### GET `/sap/bc/adt/activation/inactiveobjects` (adt-facade.mjs ~2370)

The handler is synchronous: res.type("application/vnd.sap.adt.inactivectsobjects.v1+xml; charset=utf-8").send(inactiveObjectsDocument(store.inactiveObjects(), sessionUser(req))). It returns 200 and Express adds a weak ETag (W/"len-hash"); a fresh If-None-Match gets a 304 from Express. HEAD is served by the GET route. The query is ignored: ?USERNAME=x does not filter, and every user sees the whole system-wide set. store.inactiveObjects() (osd-store.mjs:537) returns [...this.inactive].sort() using the JS default sort over the "TYPE NAME" keys, then {type, name, package: find()?.package, file}; package is undefined when the object is no longer indexed. sessionUser takes the user from the Basic Authorization header (/^Basic\s+(\S+)/i, base64 decoded as utf8, split(':')[0], || 'DEVELOPER', toUpperCase); it never reads the session. The document (adt-documents.mjs:1330 plus inactiveEntry ~1314) has this exact layout: the XML declaration, then `<ioc:inactiveObjects xmlns:ioc=... xmlns:adtcore=...>`, then the entries joined with "\n", then "\n</ioc:inactiveObjects>\n". An empty set therefore gives a BLANK LINE between the open and close tags. Each entry is 4-space indented: <ioc:entry> / <ioc:object ioc:user="USER" ioc:linked="" ioc:deleted="false"> / <ioc:ref adtcore:uri="/sap/bc/adt/<TYPES[type].adt>/<encodeURIComponent(lower name)>" adtcore:type="ADT_TYPE[type] ?? type" adtcore:name="NAME"[ adtcore:parentUri="/sap/bc/adt/packages/<encodeURIComponent(lower pkg)>"]/> / </ioc:object> / <ioc:transport/> / </ioc:entry>. The uri is "" for a type that has no adt collection. Every value is xmlEscaped (& < > ").

### POST `/sap/bc/adt/activation` (adt-facade.mjs ~2503)

The handler first reads the body as bytes (rawBody) and decodes them as utf8. Everything before the publish runs inside answered(): NotFound gives 404 ExceptionResourceNotFound (and is recorded in the miss registry), InvalidName 400, NotSupported 501, and any other throw gives 500 ExceptionInternalError in namespace org.open-steamgate.osd. Every answer is 200 or a refusal with type application/xml, and res.send makes it 'application/xml; charset=utf-8' with an Express weak ETag. The steps in order: (1) objectReferencesIn: every adtcore:uri="..." in the whole body text (raw, no XML entity decoding). The path is the uri with #fragment, ?query and a trailing /source/main stripped. It must start with a case-sensitive prefix /sap/bc/adt/<collection>/ taken from SOURCE_TYPES only (CLAS, INTF, PROG, DDLS, SRVD, INCL), so DDIC uris are silently ignored. The rest is decodeURIComponent'ed and upper-cased. A malformed % throws URIError, which becomes 500 osd 'URI malformed'. Duplicates are kept. (2) No reference gives 400 ExceptionInvalidRequest 'no object references in the request'. (3) If the If-Match header is present (an empty value counts as present): more than one reference gives 400 'If-Match activation requires exactly one object reference'. Otherwise store.read(type,name).source is read (NotFound gives 404 '<TYPE> <NAME> does not exist'), and normalizedTag (strip W/ and quotes) is compared with entityTag = sha256(source utf8) hex [0..32]. A mismatch that is not '*' gives 412 ExceptionResourceIsModified 'source changed after it was checked; check and activate again'. (4) The warm branch applies when options.transpileOnActivate !== false && store.warm()?.compiler?.primed && every reference is CLAS or INTF. It sets checked = warmActivation(...): no check and no existence test, only revision = #sourceRevision, which is undefined for a missing object. The branch goes on to publish. (5) Otherwise checked = store.activate(type,name,{activating: named}) for each reference: an abaplint check under #withOverlay plus the dependents' checks, with revision set only when the result is clean. If any result has active===false, the answer is 200 activationFailureDocument(failed.flatMap(r=>[r,...r.dependents])). (6) With transpileOnActivate===false, completeActivations(checked) runs with no built map. If it returns false, the answer is the failure document with every named object carrying 'source changed during activation; check and activate again' (E, line 1, col 1). Otherwise it is activationSuccessDocument(). (7) Otherwise, OUTSIDE answered(), the handler awaits store.publish({activate: named}): one build for the whole list, coalesced per set. warmHeaders then sets X-OSD-Build ('warm' | 'cold; recycled after a warm build: ...' | 'cold[; reason]' | 'failed; ...', host paths stripped, ASCII, 300 chars), X-OSD-Swap-Ms, and X-OSD-Closure plus X-OSD-Closure-Tests (from testClassesIn(store.root)). The outcomes: (a) ok===false with transpile.check and issues gives a failure document whose entries are the named objects first (their issues matched by case-insensitive name), then the other issue objects. (b) ok===false otherwise gives one line per named object: withoutHostPaths(error) split at \n [0], 500 chars. (c) completeActivations(checked, transpile.built) false gives the 'source changed during activation' document. (d) Otherwise activationSuccessDocument. (e) A throw gives the one-line document with the exception message. The success body is exactly: the XML declaration, `<chkl:messages xmlns:chkl="http://www.sap.com/abapxml/checklist">`, `  <chkl:properties checkExecuted="true" activationExecuted="true" generationExecuted="true"/>`, `</chkl:messages>` and a final \n. The failure document (adt-documents.mjs:1295) opens chkl:messages with 4 namespace/attribute lines (15-space continuation indent), activationExecuted="false". It then has the msgs joined by \n, each `  <msg objDescr=NAME type=W|I|E line=L href="<uri>/source/main#start=L,C" forceSupported="false">\n    <shortText><txt>MSG</txt></shortText>\n  </msg>`; with zero msgs this leaves a blank line. Then `  <ioc:inactiveObjects>`, the entries (ioc:user="", no parentUri), and `  </ioc:inactiveObjects>`. The severity rule is /^w/i to W, /^i/i to I, else E. line and column use `?? 1`, so 0 stays 0. The query (?method=activate&preauditRequested=true) is ignored. POST activation/inactiveobjects?action=... is not served and falls to the catch-all 404.

## Host dependencies

- EXISTING STORE READ (IV_TYPE, IV_NAME, IV_INCLUDE='main' -> EV_SOURCE / EV_ERROR), reading the bound store (withSystem {store}). Used only for If-Match. Caveat: READ's EV_ERROR does not carry the error class, so ABAP must tell NotFound ('<T> <N> does not exist') apart from other failures. Either add EV_JSON {code} to READ errors, or have VERDICT do the read (see below). Do NOT prefix the message the way ZCL_OSD_ADT_HOST=>OBJECT does ('OBJECT X: ...'), or the 404/500 bodies stop being byte-equal.
- NEW STORE INACTIVE: no input, bound store -> EV_JSON [{type, name, package?}] in store.inactiveObjects() order. The host sorts, so ABAP never re-sorts: JS code-unit sort and ABAP SORT agree only on ASCII. Not listed in CAPABILITIES (no screen button, like OBJECT).
- NEW STORE VERDICT: IV_JSON {objects:[{type,name}], ifMatch?: tag} against the bound store and the bound facade option transpileOnActivate. Extend the withSystem binding to {answers, store, options:{transpileOnActivate}}, because the option is per adtRouter instance and a test mounts several. It answers EV_JSON {mode:'warm'|'checked', transpile:bool, results:[{type,name,active,revision?,issues:[{severity,message,line,column}],dependents:[{type,name,issues}]}]} or {refused:{code:'NOT_FOUND'|'INVALID_NAME'|'NOT_SUPPORTED'|'INTERNAL', message}}, mirroring answered()'s class mapping so ABAP can raise the right ZCX factory with Node's exact message. The revision is #sourceRevision (sha256 over each file + NUL + file digest), an opaque string that ABAP only carries. It wraps store.warm(), warmActivation, activate(type,name,{activating}). The port-map's 'ACTIVATE (extend) -> job id' plan is superseded: no JOB and no poll, because the continuation replaces the wait.
- NEW STORE COMPLETE: IV_JSON {checked:[{type,name,active:true,revision}], built?:{"TYPE NAME": revision} (only the named keys, filtered by the continuation, never the whole transpile.built map)} -> EV_JSON {completed:bool}. It wraps store.completeActivations(results, built). It is fast (inactive.json plus copy deletes, durable writes), so it may run inside a step. It is called in step 1 when transpile=false and in the FINISH step after a publish.
- NEW continuation kind 'activation' (host JS, needs registerContinuation from feat/adt-front-up). Payload {objects:[{type,name}], checked:[...]}. It runs after the step with no work-process lock: await store.publish({activate: objects}), then warmHeaders(res, result) (testClassesIn(store.root) and withoutHostPaths stay host-side), then it runs a second dialog step ZCL_OSD_ADT_ACTIVATION=>FINISH(iv_json) and replays its record. FINISH gets {objects, checked, published:{ok, check, issues:[{type,name,issues}], error: withoutHostPaths(..).split('\n')[0].slice(0,500), built: {named keys only}} | {thrown: message}}. The registry is process-global and registering twice throws, while tests mount many adtRouters in one process. So register the kind once at module scope, and have the handler find its facade's store and options per request (for example adtRouter sets req.osdFacade = {store, options, step} before the front). The continuation context also needs a step runner (front-up passes none to handlers today): expose options.abap.step through that per-request facade object.
- Existing, unchanged: CSRF, session and ENQ resolution in ZCL_OSD_ADT_HANDLER (slice 3 B). Activation takes no lock and checks none, like Node.
- No SYSTEM kind is needed. The Basic-header user is computed in ABAP from the request headers, as Node does; the session user is not used, on purpose.

## Rationale

Everything a client sees is protocol, and protocol belongs in ABAP. That covers reference parsing, If-Match/412, the refusals, the verdict documents, the inactive-objects feed, and the success and failure documents. The work that needs the host splits into fast parts and one slow part. The fast parts are abaplint check plus dependents (VERDICT, on the order of a few seconds at most, comparable to CHECK, which the screen already runs in a step), completion (COMPLETE, file writes) and the inactive set (INACTIVE). The slow part is the build and swap or recycle. It takes about 18 s cold and 0.46 s warm, and it swaps or recycles the very process running the step. Under the FIFO rule it must not run inside the step, so it goes into the 'activation' continuation, exactly as agreed. Completion is bound to the revision digest that VERDICT returned and that the payload carries, so a save between the verdict and FINISH drops the promotion. That holds in Node today (completeActivations compares checked against built against disk), and the port keeps it by round-tripping the opaque revision. A mass activation stays one publish({activate: named}). inactiveobjects is a pure read of host state through one STORE command. It is a straight port and the cheapest win in group A (port-map listed it as S with no tests). To keep one renderer of the documents, the post-publish outcome is also rendered in ABAP (a FINISH step after the continuation) rather than by adt-documents.mjs in the continuation. Then activationSuccessDocument, activationFailureDocument and inactiveObjectsDocument can be deleted from JS once the diff test is green (editors/vscode/lib.js only parses them). The cheaper fallback renders post-publish in JS inside the continuation. It saves one step per activation (about 1 to 3 ms, negligible next to a build) but keeps two renderers of the failure document, so I would not take it.

## ABAP design

New route class ZCL_OSD_ADT_ACTIVATION implementing ZIF_OSD_ADT_ROUTE, with the rows:
- POST /sap/bc/adt/activation -> ZCL_OSD_ADT_ACTIVATION
- GET /sap/bc/adt/activation/inactiveobjects -> ZCL_OSD_ADT_INACTIVE (or the same class dispatching on path; HEAD by the HEAD->GET rule)
Both are written literally, not generated per type, and come before the HOST catch-all. POST activation/inactiveobjects stays on the catch-all, as in Node.

Shared helpers (extract, do not copy):
- ZCL_OSD_ADT_URI=>ENCODE_COMPONENT (moved from ZCL_OSD_ADT_VERSIONS=>URI_NAME): encodeURIComponent with upper-case hex.
- ZCL_OSD_ADT_URI=>DECODE_COMPONENT_STRICT: decode_segment's algorithm, but a malformed sequence raises zcx_osd_adt=>internal('URI malformed') with namespace osd (500), because Node's objectFromUri throws URIError inside answered() rather than Express's 400.
- ZCL_OSD_ADT_ENTITY=>TAG (sha256 of the utf8 source, lower hex [0..32]) and =>NORMALIZED (strip W/, quotes, trim), moved out of ZCL_OSD_ADT_VERSIONS=>ENTITY.
- ZCL_OSD_ADT_TYPES=>ALL: every TYPES entry with its adt collection, plus ADT_TYPE codes (CLAS/OC, INTF/OI, PROG/P, INCL PROG/I, FUGR/F, TABL/DT, STRU TABL/DS, DTEL/DE, DOMA/DD, TTYP/DA, VIEW/DV, DDLS/DF, SRVD/SRV, SHLP/DH, MSAG/N, DEVC/K), with a fallback: the code is the raw type and the uri is ''. A unit or diff case holds it equal to the JS TYPES/ADT_TYPE tables.
- ZCL_OSD_ADT_ACTDOC: SUCCESS( ), FAILURE( it_entries ) and INACTIVE( it_objects, iv_user ), byte-equal to adt-documents.mjs, including both blank-line cases and the 15-space attribute indent.
- New factory ZCX_OSD_ADT=>MODIFIED (412, ExceptionResourceIsModified). CONFLICT is 409 with the same type id.

GET inactiveobjects: user = Basic header (regex, decode_x_base64, utf8, text before the first ':', to_upper, default DEVELOPER). Then STORE INACTIVE, then INACTIVE doc, content_type 'application/vnd.sap.adt.inactivectsobjects.v1+xml; charset=utf-8', status 200. The ETag and 304 come from Express on replay, as for the lock route.

POST activation, step 1 (ABAP):
1. Body xstring to string (utf8). FIND ALL OCCURRENCES OF REGEX 'adtcore:uri="([^"]+)"'. For each match, cut at '#' then '?', strip a trailing '/source/main', match against the case-sensitive prefixes of ZCL_OSD_ADT_TYPES=>SOURCES in table order, DECODE_COMPONENT_STRICT, then to_upper.
2. No references: invalid_request('no object references in the request').
3. If-Match present (looked up as a header row, so an empty value counts): if there is more than one reference, invalid_request('If-Match activation requires exactly one object reference'). Otherwise read the main source (READ with a not-found code, or VERDICT with ifMatch) and compare TAG with the normalized tag; a mismatch that is not '*' raises MODIFIED('source changed after it was checked; check and activate again').
4. STORE VERDICT. A refusal maps code to factory with the message unprefixed.
5. mode='checked' with any active=false: 200 FAILURE(failed + dependents, in order). Done, no continuation.
6. transpile=false: STORE COMPLETE(checked). completed gives SUCCESS, otherwise FAILURE(named, 'source changed during activation; check and activate again', E, 1, 1). Done.
7. Otherwise return a response with continuation kind 'activation' and payload {objects: named, checked: results}. The route's own body (the answer on a system with no host) is internal('activation needs the OSD host to build') or not_supported; it is never a success document.

The host finishes: the continuation publishes, sets the X-OSD-* headers on res, then step 2 runs ZCL_OSD_ADT_ACTIVATION=>FINISH(iv_json) RETURNING ty_response:
- thrown: one-line FAILURE.
- published.ok=false with check and issues: FAILURE(named with their matched issues, using a case-insensitive name compare, then the rest).
- ok=false: one-line FAILURE with published.error.
- ok: STORE COMPLETE(checked, built named-only). completed gives SUCCESS, otherwise 'source changed during activation'.
The continuation replays FINISH's record onto res after its own headers. All three bodies use content_type 'application/xml; charset=utf-8', the bytes Express writes for .type('application/xml').send(string).

ABAP asks the host for VERDICT, COMPLETE, INACTIVE and READ only. The build, the swap/recycle, testClassesIn and withoutHostPaths stay in the continuation.

## Test plan

New test/adt-abap-activation.mjs in the adt-abap-diff pattern, on the harness of test/adt-activation.mjs: a temp root with abaplint.jsonc, a real build, generators false. Two façades, Node-only and front-up with ABAP, each over its own copy of one tree. Each compares status, content-type, content-length, ETag, body, and the X-OSD-Build value by shape (X-OSD-Swap-Ms present or absent only, because it is timing). Each sequence also asserts the reference statuses, so the two sides cannot fail alike, and asserts which rows ABAP served (activation and inactiveobjects ABAP; the continuation ran for publish cases only). Run OSD_WARM off for determinism, plus one dedicated warm case that awaits priming on both sides.

Cases:
(1) inactiveobjects: empty (the blank line); after store.write of PROG, CLAS and a DTEL in $TMP (parentUri %24tmp); a deleted-but-still-inactive object (no parentUri); Basic 'alice:x' gives ALICE, no auth gives DEVELOPER, Basic with no colon; ?USERNAME=OTHER ignored; HEAD; trailing slash; upper-case path; If-None-Match giving 304.
(2) Refusals: empty body; a body with only ddic/tables uris; If-Match with two refs; If-Match on a missing PROG (404 'PROG X does not exist'); a stale tag (412); '*', W/"tag" and "tag" all passing; an empty If-Match header (412); %zz in a uri (500 osd 'URI malformed'); a uri with #start=1,1, with ?x, and with /source/main suffix; an upper-case collection prefix (ignored, so 400); non-ASCII name.
(3) Verdict failures: a broken PROG (msgs per line, href #start=L,C); a renamed method breaking a dependent class (the dependent listed with its own msgs); a warning-severity issue (type W).
(4) A façade with transpileOnActivate:false: success, and 'source changed' via a store proxy that writes during VERDICT.
(5) Publish outcomes: success with X-OSD-Build 'cold'; a transpiler refusal that abaplint passes (named first, then the others); ok:false without issues (publish stubbed to fail with a host path in error, which must be stripped); a save landing during publish (stub writes then delegates), giving 'source changed during activation' and the object still inactive; publish throwing.
(6) Mass activation of two objects: exactly one publish call on each side (spy), and both leave the inactive feed.
(7) The FIFO proof: while a slow publish (a stub awaiting a gate) is pending, GET core/http/systeminformation (an ABAP row) answers. Red: move publish into the step and this request blocks until the gate opens.

Red proofs, each checked failing with the fix removed: no blank line in empty documents fails (1)/(3) edge; decode raising 400 fails the %zz case; COMPLETE ignoring revision fails the save-during-publish case; publish in the step fails (7); the If-Match presence test using an empty-value check fails the empty-header case; a missing ADT_TYPE entry fails the DTEL feed case.

ABAP Unit: FAILURE/SUCCESS/INACTIVE document bytes against fixtures generated from adt-documents.mjs; reference parsing; tag normalisation. Existing test/adt-activation.mjs, adt-devloop activate cases, warm.mjs, zosd-test and adt-notebook stay green with the front on (test/helpers/adt-abap.mjs). ABAP-FS conformance (--start, own port) must stay at or above the front-up figure (30 PASS / 1 FAIL / 16 MISSING); activation and inactive entries must not regress. Run npm run lint (ASCII) before offering.

## Risks

- The continuation mechanism is not on main. registerContinuation, the response's continuation field and the HOST verdict carrying it exist only on origin/feat/adt-front-up (4 commits ahead, 6 behind main). 4b cannot land before it.
- The continuation registry is process-global and registering a kind twice throws, but tests mount several adtRouters per process, each with its own store and transpileOnActivate. The 'activation' kind must be registered once at module scope and must resolve its facade per request (req.osdFacade). A per-router registration breaks the suites.
- Byte traps on the wire: Express adds '; charset=utf-8' on string sends but not on the Buffer replay, so ABAP must write the full content type itself. Empty lists leave a blank line in both documents. line/column use `?? 1`, so 0 stays 0. A malformed uri is a 500 'URI malformed' (osd namespace), not the router's 400. The upper-case collection prefix is case-sensitive here, unlike the router. An empty If-Match header counts as present (412).
- Unicode differences: JS toUpperCase/toLowerCase versus ABAP to_upper/to_lower ('ß' becomes 'SS' in JS), lenient Buffer base64/utf8 decoding versus decode_x_base64 and convert_from on invalid input (the Basic user, the body). Pin the ASCII behaviour and document the rest as known divergences, or have the host decode the body.
- Ordering: the inactive list must keep the host's JS sort. Re-sorting in ABAP diverges for non-ASCII and for keys where ' ' versus '_' order differs between collations on a system.
- A NotFound raised by ABAP does not reach facade.missed (the slice-1 gap). Node records an activation 404 in the miss registry, so the /core/http miss view loses those entries until that seam exists.
- The warm branch has no existence check: a missing CLAS in warm mode yields 'source changed during activation', not 404. VERDICT must reproduce this rather than 'fix' it, or the diff fails in warm mode. Warm priming is asynchronous, so the two diff sides can be in different modes unless warm is off or awaited.
- The FINISH step queues behind the work-process FIFO after the build. A save landing in that window now drops the promotion where Node, completing immediately, might have promoted it. This is the safe direction, but a timing-dependent diff case must not assume Node's window.
- COMPLETE writes files (inactive.json, active copies) that a step rollback cannot undo. Keep FINISH render-only after COMPLETE, so a dump cannot leave a promoted object with a failure answer.
- Not ours, but adjacent: the existing STORE ACTIVATE (the ZOSD editor screen) still runs publish() inside the caller's step, which is the same FIFO violation this design avoids. Flag it for whoever owns the screen.
- OSGo and the binary have no abaplint or build, so VERDICT is unavailable there. OSGo does not mount the front today; when it does, these rows need a CAPABILITIES-driven refusal rather than a 500.
