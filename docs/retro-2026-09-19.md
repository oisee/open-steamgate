# The day the instruments kept measuring themselves

*2026-09-19. Two sessions built a SQLScript front end, a lowering, a
conformance table and two comparison instruments. Almost every defect worth
recording was in the measuring, not in the measured, and they repeat in a
handful of shapes. Each entry names the instance, because a rule without the
case it came from is advice.*

## "Not measured" is a third value, and it is always cheaper to fake

A verdict with two outcomes almost always has a third, and it is *nobody
asked*, or *we could not tell*. It does not announce itself: it disguises
itself as whichever of the two is nearer.

Seven instances in two days, all of them ours:

| it pretended to be | what it was | where |
| --- | --- | --- |
| a difference | a row the oracle had never answered | conformance table |
| agreement | both engines refusing the statement | fused-vs-forced |
| a difference | the engine refusing our SQL, 39 times | corpus run |
| a measurement | `commit: unknown` on every deployed release | the i7 façade |
| a clean scan | a leak scan that had read no files | earlier in the week |
| a passing suite | mocha given a file that did not exist | `npm test` |
| a recording | `record` against a port with no server | `osd-replay` |

Why it keeps happening is structural rather than careless: the third value
costs a branch, a column and a word in the output, and the impersonation
costs nothing.

**And it is not inherited by proximity.** The seventh case had the correct
refusal written one layer below it, in the same file, by the same hand, an
hour earlier. Being next to a function that gets it right does nothing.
Either the rule is extracted, or it is written again at every site — and
"we already handle that" is exactly the sentence that lets the next site
skip it.

## A check is usually wider than the thing it has in mind

- `process.argv[1]?.endsWith("coverage.mjs")` also matches
  `sqlscript-force-coverage.mjs`, so importing one tool ran another tool's
  command line. Twelve files carried the same idiom.
- `type.charAt(0)` on `"STRING"` gives `"S"`, which is a short integer, so a
  column holding text was declared `INTEGER` and the hazard row could not be
  inserted at all.
- Counting **distinct** things hid the duplicate that mattered, three times:
  distinct table names hid a table scanned twice (the engine said
  `Ambiguous reference to table`, which is where we found it), and two
  earlier counts hid the same shape. A set answers *which*, when the
  question was *how many times*.

## Calibrate in the configuration the instrument will work in

The branch-comparison instrument was calibrated by running one system
against itself. In one process that gives zero differences and proves
nothing: the same clock, the same pid, the same counters — one process hides
precisely what two branches differ by. Run in **two** processes it
immediately found one real source of noise, and the rule for it was written
narrowly on purpose: a rule that swallowed "any number in brackets" would
have swallowed the row count, which is the thing the instrument exists to
show.

## An instrument that cannot go red is indistinguishable from a broken one

Every instrument written today asserts both halves: it stays quiet where
there is nothing to say, **and** it goes red where there is. The naming
check has a tree that must fail and a tree that must not. The divergence
finder has a canary body that must make it speak and a third body that
earns its silence. The conformance table prints what it collapsed.

The corollary, learnt from a test that read `typeof refTo === "function" ||
refTo === undefined`: **a test that cannot be made to fail by breaking the
code is not testing anything.** Before keeping one, break the thing it
claims to protect and watch it go red.

## A measurement can be exactly right and still answer another question

The blocker histogram that chose three hours of work was stable across runs,
ordered, and made of real constructs. It was reporting where the outermost
alternative gave up — the first character, for a body that is one block —
so it was measuring our diagnostics. The honest list, once fixed, contained
none of the constructs the old one named and three nobody had heard of.

It had announced itself an hour earlier: a count that **went up** after the
thing it named was implemented. We explained that as partial implementation,
which is a real phenomenon and was the wrong explanation. **A count that
rises after its subject is built is first evidence that the count measures
something else.**

The cheap check that caught it, three times in one day: open one of the
things the number is about and look at it. It is now a tool
(`tools/sqlscript/why.mjs`), because it is the step a tired session skips.

## A tool that explains a measurement must be the same call as the measurement

`why.mjs` exists to open the bodies a number is about. It called the same
pipeline as the coverage run — except that it passed no signature and did not
filter by language. So it could show a refusal the measurement never had, and
an hour went into looking at bodies that failed *in the explainer* while
drawing conclusions about numbers from *the report*. An explainer that
reproduces a slightly different program explains a different program, and it
does so convincingly.

The same shape, caught earlier by luck rather than design: `forceability()`
predicts statically what `runEager()` does live, and the two drifted apart the
first time the seam changed under them. They are held together now by a test
that runs both and compares — which is the general answer. **Two paths to one
answer need a test that runs both, or they are two answers.**

## A workaround needs a guard that goes red when it stops being needed

`abaplint` does not parse `!VALUE(x)` — the form SE24 generates — and loses
every parameter of the class when it meets one, so a body refuses with
"unknown table variable" three lines below where ABAP declares it. The fix is
a one-token normalisation on the way in, deliberately not a reimplementation
of somebody else's parser.

The test that matters is not the one asserting the workaround works. It is the
one asserting **the reason it exists**: that `abaplint` still refuses the
original form, and in the specific way it refuses it. That test goes red on
the day upstream fixes the defect, which is the only cheap way to learn it —
nobody reads release notes for a parser. It has a precedent here: `npm run
parked` complains in both directions, at a branch nothing explains and at an
entry naming a branch that is gone.

Two things such a guard must do or it rots: assert the *specific* failure
(here, that the class loses **all** parameters, not that something threw), and
say in its own message what to do when it goes red — remove the
normalisation, delete the ANORMALIES entry, re-run the corpus count. A red
test that does not say what it means costs an hour before it saves one.

## Name the metric no wider than what it measures

"8% of the corpus" meant *parses*, while *runs* was zero, and it would have
been quoted a week later as "8% works" — by us. Splitting it into three
numbers (parsed / lowered / actually run) turned one comfortable figure into
a picture, and every later finding came out of the gap between two of them.

The same correction was needed twice more the same day: "all 67 compare
fully" was a static property with the word *compare* in it, and "7 bodies
compared, no divergences" was true and meaningless until the number beside
it — how many of the seven could diverge at all — was printed with it.

## Measure the second property when you add the second use

A comment said a cast could pass through to DuckDB because *it raises like
HANA*. True, and silent about rounding: DuckDB rounds where HANA truncates,
so `1.7` became `2`, and the test for that line asserted the text of the
pass-through, which is why it was green for as long as the defect existed.

The defence is not to write more carefully. It is to state **what was
measured** rather than the conclusion: "raises on `'oops'` — measured" is
immune to being read as a guarantee, and the next person sees at once that
rounding is not in it.

## A tool tested only on the specimen made for it reports on the specimen

Three instruments, three hours apart, one shape:

- **`npm run preview:closure`**, written to find node builtins the preview
  bundle reaches, read the webpack config with a 1200-character window and
  swallowed the config's own `module:` section — so it reported `module` as
  covered. `module` is the single builtin it exists for. It was green, and it
  was green about itself.
- **a guard over the tools' entry-point idiom** went red on
  `tools/osd-main.mjs`, which quotes the bad form in its own explanation: a
  check that reads whole files finds its confirmation in the file that
  explains it.
- **the CDS check**, run over the whole tree rather than over the fixture it
  was written against, found two at once: a table function, which has no
  `SELECT` by construction and was being called broken, and a fixture whose
  complaint was right about the object and wrong about the system.
- **the CDS check** was written against a fixture and passed. Run over the
  whole tree — thirteen views instead of one — it flagged two, and **neither
  was a defect of a view**: one was a `define table function`, which has no
  SELECT by design, and one was a fixture the object store indexes and the
  build excludes.

The rule is not "test more widely". It is that a specimen built for an
instrument answers the instrument, and the answer is about neither the
system nor the instrument. The cheap version: run it once over everything
you have, before you believe the first green.

## "Not supported" and "cannot be read" are one word too few

`parseDDLS` skips a table function with "no select", and the check turned
that into an error — telling a person their object was broken. The kinds a
generator does not handle are silent; the ones it cannot read are not. The
third value again, and this time it was **inside a fix for the third value**,
written the same afternoon.

## A comment describing intent is indistinguishable from one describing behaviour

`await import()` does **not** keep a module out of a webpack bundle — webpack
makes a chunk and `LimitChunkCountPlugin({maxChunks: 1})` glues it back in.
The store was opened lazily *so that* abaplint would stay out of the service
worker, and a comment said so. The bundle does not read comments: thirteen
errors, GitHub Pages red.

Twin, the same day, one floor down: `test/setup.mjs` says the AMDP
destination "is installed whatever the database is" — three lines below the
early return that skipped it for the preview.

The only thing that keeps a module out is `IgnorePlugin`. The only thing that
makes an intention true is code that has been run.

## A log truncated by the command that produced it is not a log of nothing

`npm run unit 2>&1 | tail -15` over a seventeen-line file, and eight test
classes "never ran". They ran; they were in the middle. `tail -15` and "it
did not run" look the same on a screen, and the same knife cut twice in one
day — the morning's `coverage.mjs` header went through `tail -25`.

Write to a file and grep the file. The instrument is honest, the output is
honest, and the lie is made between them.

## Two variables changed, one noticed

Three experiments, all of them ours:

- a `.clas.xml` added **and** the log read differently — the file got the
  credit for four hours
- a suite run "with the change" while a second suite shared the machine,
  against a control run "without the change" and alone
- a fix measured in a planted worktree that did not contain it, because
  `osd-branch` plants the committed HEAD and the change was unstaged

The control costs one run. Finding out afterwards costs the afternoon.

## A number cannot travel without the state it was taken in

Two sessions read the object store 55 seconds apart: 1140 and 1134. Both
correct, of two different systems — the library clones are **one checkout
shared by every worktree**, and one session had moved `open-abap-core` onto a
PR branch carrying exactly the six objects of the difference.

`npm run branch -- state` prints the count, the types and the HEAD of every
library together, because one of those quoted without the others is a
measurement of an unnamed system.

## Hash the thing, not its representative

`gen/` was in the generation hash and is **written by the build**, so the
first build of a fresh tree hashed an empty `gen/` and the second hashed what
the first had written: two builds, no edit, two names. The cause was one
line — `NOT_AN_INPUT` excludes `.mjs`, so a generator's own code was not an
input while its output was.

The same error was then offered as the fix for the binary: hash
`join(root, "tools")`. A compiled binary executes its **own embedded
copies** and never reads those files. Each host now names what it will run,
and the consequence is that two hosts legitimately name different
generations — which was a true statement about the system that an equality
assertion had been hiding.

And taking `gen/` out removed an accidental protection nobody had noticed: a
cache hit skips the generators, so edit → build → revert → build left `gen/`
holding the edit. The served system was right and the working tree was not,
and those two had agreed by accident.

## A pair that must agree, and a pair that must differ

Five of the first today: two keyword lists, two copies of a refusal
predicate, two box widths, a three-entry library list against a six-entry
config, a port written twice in a file that could be told the port. Each was
a defect deferred to the first divergence.

The converse is sharper and was learnt three wrong answers in a row: **two
things that must differ cannot be collapsed into one, and inferring the
difference from the shape of the data instead of declaring it fails
silently.** The build asks "can the transpiler read this file"; the object
store asks "is this an object of the system". No pattern over the exclusion
list turns one question into the other, because the difference is an
intention — and an intention is declared, never derived.

## A fixture is not an object of the system, and a test's need for one is not a reason

`/test/fixtures/` was kept in the object store on purpose: a façade test read
`ZDEMO_EDITOR` through it as a system object, and a folder-shaped exclusion
had once removed it. So the system contained an object the build had never
compiled, and a check of it was **right about the object and wrong about the
system** — it selects from a table the system does not have.

The fix is the rule rather than a second place: the folder joined
`not_in_system`, and the test that needed a plain program now reads one that
is in the system (`ZOSD_TEST_DEMO_PLAIN`). That is the second confirmation of
the same rule in a week — after `gen/segw-editor` — and both times the
divergence showed up not as something missing but as **a false statement
about the system**.
## Читатель, который не умеет сказать «их было больше»

Алиса нажала Execute с тремя галками и получила одну колонку. Причина не в
экране и не в выборе: `get_form_field` возвращает **первое** совпадение и не
имеет способа сообщить, что совпадений было несколько. Группа чекбоксов шлёт
по параметру на галку (`c=A&c=B`), и множественный выбор молча становился
первым.

Интереснее, что колонки были **покрыты тестом с самой второй волны** — и он
не поймал. Потому что тест сам сочинял запрос, `c=TRAVELID,STATUS`, а это
написание производят **ссылки**, не форма. Экран пишет выбор в двух
написаниях, тест проверял одно. Новый тест не составляет запрос вовсе: он
читает форму со страницы и отправляет её так, как отправил бы браузер.

Общая форма, и она не про HTML: **тест, который сам придумывает запрос,
проверяет только ту кодировку, которую придумал.** Если у экрана два
производителя одного и того же параметра, тест обязан брать запрос у экрана.

## Красная сборка не означает отсутствия сборки

Апстримный транспилятор на HEAD не проходит `npm run compile`: одна ошибка
типов в `src/chunk.ts`, она же на нетронутом чекауте. Естественный вывод —
«тесты прогнать нельзя, оговорюсь в PR» — оказался неверным. `tsc` при
ошибке типов **всё равно выдаёт JS**, а их mocha гоняет `build/test/**/*.js`.
Сборка была всё это время: 334 зелёных, 6 pending, ноль падений.

Это близнец всего, что мы ловили сегодня, только с другой стороны. Весь день
был про зелёную команду при нерабочем продукте — обрезанный `tail`, генерация
десятичасовой давности, `curl`, попавший в чужой порт. Здесь наоборот:
**команда красная, продукт рабочий**, и сигнал разошёлся с артефактом в
благоприятную сторону, отчего его так же легко принять на веру.

Правило то же, что и в 8.4, и оно симметрично: **судят по артефакту, а не по
коду возврата.** Если бы я поверила красному, в PR поехала бы оговорка
«тесты не прогнал» — а это в чужом репозитории читается как «он не
проверял», и стоила бы она дороже самой правки.
