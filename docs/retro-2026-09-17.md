# Retrospective, 2026-09-16 → 17: two days that turned the demo into an instrument

*Written at the end of the session that did it. Facts first, then what they
taught, then what is owed.*

## What happened, in order

1. **Layers, library transpile, one binary** (E.1, N3, SP4). The
   `input_folder` list became the layer order (later wins, duplicates
   refused), the transpile became a library call proven equal to the CLI,
   and the whole workbench became a Bun binary; Node SEA and a plain bundle
   were measured as control groups (26.9 runs external imports, 26.3 does
   not). Zork 33/33 on every host.
2. **Packs** (E.2). A directory with an `osd-pack.json` is content: ABAP,
   rows, tables, a page, tiles. Then the o4d demo, Zork and, today, the
   light-show became packs; a pack may *fetch* its sources from a
   repository at a commit and overlay the few files it needs changed.
3. **Work processes** (B.12). One core was saturated while fifteen idled;
   a pool of runtime children with a socket pinned per process took the
   frame rate from 474 to 1646 f/s here and 111 to 369 on the i7, with no
   change to the ABAP or the page, which was the constraint Alice set.
4. **The demo as an oracle.** The same ABAP on A4H answers the same frames,
   so a recording is an oracle and a diff is the test. Eight anomalies in
   two days, every one measured on A4H with a throwaway ABAP Unit probe
   before anything was changed; all 22 scenes attributed
   (`docs/frame-comparison.md`).
5. **Upstream.** Six issues (#1859–#1861, #1865, #1866 in the transpiler,
   #4302 in core) and four PRs (#1862, #1863, #1864, #1867), one commit
   each with its test, from branches inside the repository so Regression
   runs. Lars merged three within the morning of the 17th.
6. **Pages, alive again.** The preview had not deployed since the 13th;
   four causes in a row (a stale lock file, webpack cleaning the
   generation store, a `node:sqlite` import in a worker, the runner
   linking two of three packages), then two more once it ran (upstream
   `open-abap-core` lacking the held patches; `WRITE` with no stdout in a
   worker). Now the launchpad, the demo, Zork and the light-show run in a
   browser with no server.
7. **The light-show** (E.8, first milestone). `sap-tui --record` writes
   the composed SAP GUI screens as a stream, an ABAP channel hands it out
   by line, a page paints it in a Signature window with the music. From
   idea to a tile on Pages in one afternoon, because every part already
   existed: the DIAG viewer, the pack mechanism, the channel pattern, the
   media path.

## What worked

- **Measure, then change.** Every anomaly went to A4H before a line moved.
  The critic pass caught the one place this slipped: the APPEND issue
  claimed a table of zeros where the old code rounded to −1, 0, 1, and the
  reproducer index chosen (65, a quarter turn) was the one where both sides
  agree. Ten minutes of measurement rewrote the issue before Lars saw it.
- **Small PRs from inside the repository.** One commit, one test, one
  fix, Regression visible in the checks. Three merged the same morning.
- **Reuse instead of building.** The light-show took an afternoon because
  nothing new had to exist: the viewer already composed screens, the pack
  mechanism already carried media, the ZO4D page already showed how a
  channel hands out frames. The recorder was 150 lines of Go.
- **Green means a specific thing.** "Nine browser tests pass locally"
  meant nothing about the runner three times (packages linked here and
  not there, a library clone with patches here and not there, a file git
  ignored here and never had there). The workflow now pins three things
  by commit, and `docs/frame-comparison.md` says what each number is a
  number of.

## What went wrong, and the rule each left

| what | cost | rule |
| --- | --- | --- |
| `pkill -f <pattern>` killed the shell that ran it, twice | a redeploy that reported success on a dead process | stop by port owner (`ss -ltnp`), never by command-line pattern; `scripts/osd-restart.sh` does it right |
| background tasks stopped "for low memory" with 10 GB free | three restarts of the sweep | long-running servers go `setsid nohup … & disown`, out of the harness's task list; recordings run in the foreground in ten-minute chunks |
| `*.jsonl` in `.gitignore` swallowed the pack's recording | a green local build, a red runner, an hour | a pack asset never takes an extension the repository ignores; the recording is `.ndjson`; `git status --untracked-files=all` before calling a pack committed |
| an ABAP backtick literal carries `\\n` unchanged into JavaScript | the player counted one line per batch and never got ready | `String.fromCharCode(10)` in a page written from ABAP, or a `|…|` template with `\n` outside backticks |
| `status` in a page script is `window.status` | the status line never changed | never name a page variable after a window property |
| the base image of a database file was named by the schema alone | a media object in the generation and not in the table, 404 | the image is named by schema *and* rows; the tables the generation writes are rewritten from it on every boot (B.13) |
| `cp` failed before the heredoc that followed it | an XML that was never written, a data file with no object | one action per command when the second depends on the first, or `set -e` |
| the deploy script polled the ssh alias `i7` over HTTP | four idle minutes per deploy | resolve the address once (`ssh -G`) and use it |
| pushing a doc commit while a test still failed (`;` not `&&`) | one red Pages run | push only on green, in the same chain that ran the test |

## The one thing to carry forward

The demo was not written to test anything, and that is why it tests
everything: it uses the language the way application code does, in
combinations nobody would think to assert, and prints the answer as
numbers. Any system that can run the same ABAP as a real one and compare
the output has this instrument for free. Keep the recordings, keep the
oracle, and let it name the next anomaly before a user does.
