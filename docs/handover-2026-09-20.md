## What is open, in the order it unblocks

### 1. Writing through OData — the last piece of G.5

`ZOSD_ICF_SRV` is `creatable/updatable/deletable: false`. The Fiori
application therefore only displays; the only writer is the HTML screen at
`/sap/bc/osd/sicf/`, which calls `ZCL_OSD_ICF=>SET_ACTIVE`.

To finish: allow the write in `src/icf/zosd_icf.stg.yaml` **and route it
through the bookkeeping**. The generic SADL write path
(`zcl_stg_sadl_dpc` → `zcl_stg_tab_icfservice`) writes the row directly and
knows nothing about `ZOSD_ICF_ORIGIN`.

**What an unmarked edit actually costs** (stated exactly, because the
stronger version reached three commit messages before anybody read the
branches back — see `docs/registry-drift.md`):

```
object unchanged, row marked or not   KEEP     the edit stands
object changed,  row marked EDITED    ASIDE    replaced, kept, reported
object changed,  row NOT marked       REPLACE  replaced, silently
```

So the harm is not "the next build undoes it". It is "on the day its object
next changes, it goes without a word" — quieter, later, and not connected by
anybody to the build that did it.

`SET_ACTIVE` already lives on `ZCL_OSD_ICF` rather than on the screen, for
exactly this: a rule about what **every writer must do** is inherited only if
it lives in what they both import. `tools/osd-dialog-step.mjs` is this tree's
worked example of the alternative, in three hosts, two of them wrong.

Blocking nothing else. Do this first.

### 2. Security of the write path

Found by codex-sol and not yet addressed:

- **No CSRF token and no authorization** on `/sap/bc/osd/sicf/`. It is a POST
  now, which stops a link or a crawler, and a POST is not CSRF protection: a
  hostile page can submit a cross-site form. While the only writer was our
  own screen this was bounded; opening OData writes makes it real.
- `SET_ACTIVE` is a non-atomic update / select / delete / insert. Two writers
  race; there is no lock and no optimistic condition. It does now refuse a
  node that does not exist.

### 3. The missing fields of a real SICF

Alice's G.5 specification (backlog, 2026-09-18) names them: service
parameters as name/value pairs, logon data (client, user, language, the order
of the authentication procedures), error pages, the session timeout, the
stateful flag, aliases. Only the active flag exists today, and it is the one
the screen writes.

These are DDIC tables plus CDS views plus entity sets — the shape is already
worked three times over (`src/status/`, then `ICFDOCU` this morning).

### 4. Two recorded, not fixed

- **`ZOSD_ICF_ASIDE` is lossy.** It keeps the node, the URL, the handlers as
  a comma-joined list, when and why. The handler **order and type** are lost
  and the descriptions are not kept at all: enough to see what was replaced,
  not enough to put it back.
- **The content hash is not canonical.** `JSON.stringify` over the service
  row depends on property insertion order and drops `undefined`; the handler
  chain is joined with a delimiter that could appear in a value; the digest
  is truncated to 64 bits. One producer today (`rowsOf`) is why it has not
  bitten. A second producer is what would make it bite.

### 5. Open notes with a way to close them

- `NOTE-2026-09-20-i18n-not-intercepted` — the preview's service worker does
  not see an application's i18n request at all (`fromServiceWorker` is false
  for it and true for `Component.js` on the same prefix). Affects every Fiori
  app in the preview, predates this work, consequence is a fallback and a red
  line in a network tab. First place to look: a synchronous XHR from
  `ResourceModel`. `test/e2e/preview.spec.mjs` excludes `/i18n/` and names
  the entry — **when the defect goes, the exclusion must go with it.**
- `NOTE-2026-09-20-generation-hash-moved` — closed, kept because the method
  generalises: snapshot the file list and sizes of `inputsOf(root)`, poll
  `hashOf` once a second, diff on the first change. Thirty lines; it names
  the file or says the defect is in `hashOf` itself.

### 6. Not ours to decide

- The OData front's own `*.sicf.xml`. **Do not write one.**
  `/sap/opu/odata/sap/` is a node a real system delivers; our object there
  would be at best a fiction. It lives in `src/icf/nodes.json` with
  `"mount": "elsewhere"` and a written reason.
- `SAP_DELIVERED` (`tools/osd-nodes.mjs`) names three paths a real system
  delivers that our `*.sicf.xml` claim. `tools/osd-abapgit-zip.mjs` refuses
  them outright. **What an import would actually do is not established** —
  abapGit calls `insert_node( icf_name = orig_name, icfparguid =
  find_parent( url ) )` and decides insert-versus-update by the file's name,
  so it might nest, collide or fail. Establishing which needs a system, and
  **A4H is only touched when Alice asks.**

## Standing constraints, verbatim

- **SAP systems: only the A4H sandbox, only when Alice asks.**
- **Never commit captures** (`*.pcap`, `*.jsonl`) — they carry real logons,
  session GUIDs, credentials.
- **Public repo — no live identifiers.** No real hostnames, usernames, IPs,
  transport IDs or customer namespaces in any tracked file. Operational
  scratch goes under `.local/` (gitignored). *This file obeys that: the i7 is
  named by its port, not its address.*
- **Sending upstream is gated by a critic, not by an ask.** A merge, a
  force-push, or a push to a repository that is not ours still asks first.

## Five traps this day paid for, that a reader would otherwise pay again

1. **A check that has never been green is not an instrument.** `tests.yml`
   was red on all six runs since it was written, including the run of the
   commit announcing it; GitHub Pages served yesterday's build for nine
   hours behind twenty-two red preview runs. Both were fixed only because
   somebody looked at the check rather than at the file.
2. **A number answers the question it was computed for, not the one it is
   read under.** "1101 passing" was true of 90 files out of 101; twelve CI
   failures were one missing folder; `synchronized: false` was a suite
   writing into `src/`.
3. **The same rule applied where the consumer is different.** An absolute
   component URL, an absolute data source and a `%2e` in a file name all
   worked on a system and failed on GitHub Pages — and in each case a
   comment two files away already described the hazard.
4. **A test can check the furniture and look like it checks the function.**
   `libraryState()`'s test asserted that *some* configured library is not a
   clone, which was true only because one folder happened not to be.
5. **A wrong explanation is worse than an open question**, because the next
   person stops looking. One was published in a commit message here and
   corrected by another.
