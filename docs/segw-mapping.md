# SEGW "Map to Data Source": what the generator writes and where it learned it

`tools/segw-gen.mjs` turns a SEGW project tree (`<project>.iwpr.xml`) into
the `_MPC` / `_DPC` base classes. Since 2026-09-12 it also writes the code
SEGW puts into the DPC for an operation that is *mapped* to a data source,
and the SADL delegation for every kind of SADL binding. This note records
the oracle projects, the templates, the tree tables that drive them, and
what cannot be reproduced without a system.

## Oracles

SAP-delivered projects exported from the A4H sandbox with abapGit (kept under
`.local/corpus-sap/`, never tracked: SAP-proprietary):

| package | project | what it shows |
|---|---|---|
| `/IWBEP/EPM_DEVELOPER_SCENARIO` | `/IWBEP/EPM_DEVELOPER_SCENARIO` (2012) and `/IWBEP/EPM_DEV_SCENARIO_2` (2013) | every operation mapped to an RFC module of `SEPM_GATEWAY_SERVICES` |
| `S_EPM_CDS_EXP` | `SEPM_HCM_SCENARIO` (2014) | CDS through SADL + create/update/delete mapped to RFC |
| `/IWBEP/740_SAMPLE_BASIC` | `/IWBEP/GWSAMPLE_BASIC` | search-help data sources (`VH_*Set`), complex type over a DDIC structure, actions bound to an entity |
| `S_EPM_SADL_GW_DEV_SCEN_TX` | 2014 | SADL over an EPM business object (`EPM~IF_EPM_ADDRESS~...`) |
| `S_UCON_HTTP_GW_BASIS` | `UCONHTTP` | SADL over CDS (`CDS~`), read-only |
| `S_ESH_SEARCH_ODATA` | `ESH_SEARCH`, `ESH_SEARCH_VERSION2`, `ESH_SEARCH_ANNO_REF` | a redefined service (version 2) and an annotation model project |
| `S_EPM_GATEWAY` | (function groups) | the abapGit `*.fugr.xml` the RFC templates need for signatures |

The check is `npm run segw:gen -- <folder> --check --lib .local/corpus-sap/S_EPM_GATEWAY`.
Loose compare (whitespace, case, declaration order) because the deliveries
were generated by three SEGW releases; what is left per class is listed at
the end.

## Data-source kinds in the tree

`/IWBEP/I_SBD_DS.DS_TYPE`: 2 = RFC/BOR (`FUNCTION_NAME`, `DS_GROUP` = function
group, `RFC_DEST`, `LOG_DS_ATTR` = the BAPIRET2 table), 4 = SADL
(`DS_GROUP` = `DDIC~<table>`, `CDS~<entity>` or `EPM~<bo>~<node>`), 5 = DDIC
structure (only types), 6 = search help (`NAME`, `MAX_HITS_DS_ATTR`).

A mapping header (`SBD_MH`) hangs under the *operation* node (RFC, search
help) or under the *entity set* node (SADL) and points at the data source.
Its rows (`SBD_MP`) map one property (`PROPERTY_PATH`) or one constant
(`CONSTANT_VAL`, quoted) to a parameter path (`DS_ATT_PATH`: `IV_X`,
`ES_X\FIELD`, `ET_X\FIELD`, `RESULT_LIST\FIELD` for search helps) with a
direction (`I` request → module, `O` module → response). A range table gets
four `SBD_MR` rows (`SEMANTICS` H/L/O/S) naming its components.

The generated artifacts (`SBD_GA`) list, besides the four classes, one
`BOP` interface per RFC data source (`/IWBEP/IF_SEPM_GWS_BP_GET_DE1`), a
copy of the DDIC types the module uses; newer trees carry `RFC_NAME` on
that row, older ones only the name (cut to 30, numbered on collision).

## Templates (DPC)

**RFC** (`segw-gen-mapping.mjs`, `rfcMethod`): one `DATA` per mapped
parameter typed `<bop-interface>=><type>` when the tree lists the
interface, else the DDIC type from the function group; `ls_<table>` lines
for table parameters; the request mapped in (converted keys for read /
update / delete, `read_entry_data` for create / update, filter select
options converted per property into range tables or a scalar, constants
assigned and appended once); `get_rfc_destination`; `CALL FUNCTION` twice
(local in a `TRY`, or `DESTINATION` with `communication_failure`); then
`rfc_exception_handling`, `rfc_save_log` on the log table, and the outputs
mapped back (`er_entity-x = es_y-x`, or the `LOOP ... FROM lv_skip TO lv_top`
over the result table). Create and update and delete `commit_work`; create
reads the entity back through `/iwbep/cl_sb_gen_read_aftr_crt`. When the
operation sits behind a navigation property, the read and query templates
take the key from the source entity set (`get_converted_source_keys`) for
every referential constraint that feeds the mapped key.

**Search help** (`shlpMethod`): filter select options → `DDSHSELOPS` rows
(`shlpfield`, `shlpname`), `get_search_help_values` through the
`/IWBEP/IF_SB_GENDPC_SHLP_DATA` implementation the class gets, then the
field/value result list unpivoted into `et_entityset` record by record; the
read variant builds one `EQ` row per key.

**SADL** (`sadlMethods`, existed before): `if_sadl_gw_dpc_util~get_dpc`
with the `<sadl:definition>` XML now takes the binding type from the tree
(`DDIC`, `CDS`, `EPM`).

The function-module signature comes from an abapGit `*.fugr.xml`; the CLI
takes `--lib <folder>` (repeatable), the closure tool looks in the repo.
Without it the method stays a stub with a comment and a warning.

## What changed in the MPC from the same oracles

- entity-set flags: a plain `X` in the tree means set, no field or the
  `_XU` marker means not set (was: no field = set);
- `IS_NULLABLE`, `SEMANTICS` (`set_semantic`), `AS_ETAG` (`set_as_etag`);
- decimals: `set_maxlength( PROP_PRECISION )` + `set_precison( SCALE )`;
  a DateTime with a precision: `set_precison( PROP_PRECISION )`;
- inline structure types: `p length <bytes> decimals <scale>` for
  `Edm.Decimal`, `f` for `Edm.Double`, `TYPE_KIND P` rows from the tree;
- complex types over a DDIC structure (`bind_structure ... iv_bind_conversions`);
- actions: `set_action_for`, `set_return_complex_type`, parameter
  `set_maxlength`;
- every generated name stops at 30 characters (`TS_`/`TT_`/`GC_` + 27,
  `DEFINE_` + 23 of the entity name; `ESH_SEARCH` has entities of 38); two
  entities that collide after the cut: the one whose name fits keeps it,
  the other loses one more character.

## Not reproducible offline (left as known differences)

- `set_conversion_exit( 'ALPHA' )` and the text-element labels: SEGW reads
  the data element at generation time; the tree does not carry them;
- BOP interfaces themselves (flattened DDIC copies) are not generated;
- redefined services (`SBO_MR.REF_TYPE = EXT`: MPC `extend_model`, DPC
  inheriting the referenced `_DPC_EXT`) and annotation model projects
  (`PROJECT_TYPE 3`, `_APC` classes) are recognised and skipped;
- the "redirect" a 2013 read template writes when a navigation's source key
  is not the target's key (calls the source entity's `GET_ENTITY` and maps a
  field of it); the `get_expanded_entity(set)` redefinitions of the 2014
  SADL template (later releases write the conditional/patch ones we do).

## What the runtime still lacks for these classes

`npm run segw:closure -- --corpus .local/corpus-sap --lib .local/corpus-sap/S_EPM_GATEWAY`
after generation, odata bucket (what open-abap-odata has to grow, in the
order the generated classes hit it):

- `/iwbep/if_mgw_odata_property`: `set_semantic`, `set_as_etag`;
- `/IWBEP/IF_SB_GENDPC_SHLP_DATA` (`tt_result_list`,
  `get_search_help_values`), `/iwbep/cl_sb_shlp_data_factory`,
  `/iwbep/if_sb_shlp_data`, DDIC `DDSHSELOPS`: the search-help runtime;
- `/IWBEP/MGW_BOP_RFC_EXCEP_TEXT`, `/IWBEP/T_MGW_TECH_PAIRS`,
  `/IWBEP/S_MGW_TECH_PAIR`;
- `/iwbep/cl_sb_gen_read_aftr_crt` (`set_keys`, `set_entityset_name`,
  `set_entity_type_name`): the read-after-create request context;
- `io_tech_request_context->get_source_entity_set_name`;
- `/IWBEP/SUTIL_LOG_HEADER`, `/IWBEP/SUTIL_ERROR_CTXT_INFO` (the error-log
  service's own structures, not Gateway).

The RFC templates type their variables through the BOP interface when the
tree lists one; the closure tool lints the repo's `*.intf.abap` alongside
the generated classes so those resolve.
